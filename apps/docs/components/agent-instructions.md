# Set up a Fumadocs site

Instructions for AI coding agents, follow the steps in order. Fumadocs docs: https://fumadocs.dev/docs, append `.mdx` to any docs page URL to get it as Markdown, https://fumadocs.dev/llms.txt lists all pages.

Framework guides are at `https://fumadocs.dev/docs/<framework>/<page>.mdx`, where `<framework>` is `next`, `react-router`, `tanstack-start`, `waku` or `astro`. Links below use `<framework>`, replace it with the framework of the project.

## 1. Keep the docs site separate

Create the docs as its own app: a new directory or repository, or a new workspace package (e.g. `apps/docs`) in a monorepo.

Don't add Fumadocs to an existing marketing or product app unless the user explicitly asks for it: Fumadocs UI ships global styles and its own layouts, mixing them into an unrelated app leads to style conflicts, coupled deployments and harder upgrades. If the user does want it inside an existing app, skip step 2 and run the CLI in the app. It adds the docs in a dedicated route group, and supports Next.js, Waku, React Router, TanStack Start and Astro:

```bash
npx @fumadocs/cli@latest init
```

- It asks before overwriting a file. `--yes` overwrites every file the command writes, such as `lib/source.ts`, so check `git status` before running it and review the diff after.
- Without a terminal, it doesn't prompt: existing files are kept unless you pass `--yes`, and a missing choice fails with the flag to pass.
- `--i18n` sets up internationalization.

Or follow the manual installation guide of the framework:

- Next.js: https://fumadocs.dev/docs/next/manual-installation.mdx (Recommended)
- Waku: https://fumadocs.dev/docs/waku/manual-installation.mdx (Recommended if user prefer Vite)
- React Router: https://fumadocs.dev/docs/react-router/manual-installation.mdx
- TanStack Start: https://fumadocs.dev/docs/tanstack-start/manual-installation.mdx
- Astro: https://fumadocs.dev/docs/astro/manual-installation.mdx

## 2. Scaffold with create-fumadocs-app

Use the official scaffolder, it produces the reference project structure with search, `llms.txt` and OG images configured. Templates:

- `+next+fuma-docs-mdx` (Next.js): the default, use it unless the user prefers another framework.
- `waku`, `react-router`, `tanstack-start`, `astro`: when the user already uses that framework.
- `+next+fuma-docs-mdx+static`, `react-router-spa`, `tanstack-start-spa`: when the site must be fully static (hosted on a CDN).

Run it non-interactively (requires Node.js 22+), `--yes` uses defaults for unspecified options and `--pm` selects the package manager:

```bash
npx create-fumadocs-app@latest my-docs --template +next+fuma-docs-mdx --install --yes
```

All options: https://fumadocs.dev/docs/cli/create-fumadocs-app.mdx

Don't hand-write the setup from memory or pin older versions, the generated project is the source of truth. Don't edit the `.source/` folder, it is generated by Fumadocs MDX.

## 3. Write content

- Pages are MDX files in `content/docs`, the folder structure defines the URLs. Every page needs a `title` in its frontmatter, and ideally a `description`.
- The layout renders the frontmatter `title` as the page heading, so don't start the content with a `# H1` that repeats it.
- A `meta.json` file orders the items of its folder. `pages` lists file and folder names without extensions, and names that match nothing are dropped without an error. A folder with a `pages` list hides pages that aren't listed, so add `"..."` to the list to include the rest: https://fumadocs.dev/docs/<framework>/page-conventions.mdx and https://fumadocs.dev/docs/<framework>/navigation.mdx
- Frontmatter keys that the collection schema doesn't define are dropped. To add one, extend the schema: `pageSchema.extend({ ... })` in `lib/source.ts`, or in `src/content.config.ts` on Astro.
- MDX components must be registered in the MDX components file, `components/mdx.tsx` (under `app/` or `src/` outside the Next.js template).
- The Next.js and Waku templates resolve relative file links like `[Guide](./guide.mdx)` with `createRelativeLink`. On React Router, TanStack Start and Astro, link the URL instead, like `/docs/guide`.
- Write callouts as `<Callout type="warn">...</Callout>`. GitHub alerts (`> [!NOTE]`) render as plain quotes, and `:::note` admonitions need the admonition plugin: https://fumadocs.dev/docs/headless/mdx/remark-admonition.mdx
- When migrating existing Markdown docs, move them as-is and keep their content, only adjust frontmatter and links. Supported syntax and components: https://fumadocs.dev/docs/<framework>/markdown.mdx
- Site name and links live in `lib/layout.shared.tsx`, GitHub info in `lib/shared.ts` (Next.js template; other templates put app code under `app/` or `src/`, check the generated README).

## 4. Check

Run `npm run dev`, open `/docs` on the local URL it prints and make sure pages render.

Before you finish, run `npm run types:check` (when the project has the script) and `npm run build`. Fix errors by reading the docs of the relevant feature rather than removing it. To find broken links in content, see https://fumadocs.dev/docs/<framework>/markdown/validate-links.mdx (not available on Astro).

## 5. Deploy separately

Deploy the docs app as its own project on the hosting provider: https://fumadocs.dev/docs/<framework>/deploying.mdx

To serve it under the main domain, use a subdomain like `docs.example.com`, or route `/docs/*` from the main site to the docs deployment (e.g. Next.js Multi-Zones). Keep the docs under the default `/docs` route so both options work.

## Markdown options

Global Markdown options, like remark and rehype plugins, go in `source.config.ts` at the project root. The file is optional: the templates define collections in `lib/source.ts` with the Macro API, and you can create `source.config.ts` next to it: https://fumadocs.dev/docs/mdx/global.mdx

On Astro, pass them to the `fumadocs()` integration in `astro.config.mjs` instead.

## Upgrading

Upgrade every Fumadocs package together, with the commands of https://fumadocs.dev/docs/<framework>/upgrade.mdx
