## Pages

Each MDX file in `content/docs` is a page:

| File                             | URL                   |
| -------------------------------- | --------------------- |
| `content/docs/index.mdx`         | `/docs`               |
| `content/docs/hello.mdx`         | `/docs/hello`         |
| `content/docs/guide/install.mdx` | `/docs/guide/install` |

The prefix is the `baseUrl` of your source. Order the sidebar with a `meta.json`:

```json title="content/docs/meta.json"
{
  "pages": ["index", "hello", "guide"]
}
```

Besides `title` and `description`, frontmatter takes `full: true` to use the full width of the page, see [Full Mode](/docs/ui/layouts/page#full-mode). Add your own fields with a [schema](/docs/astro/collections#schema).

Fumadocs on Astro has the same conventions and Markdown features as on other frameworks:

## MDX Components

MDX files can use components without importing them, like `<Cards>` above. They come from the `components` module, a file whose default export is your MDX components:

```js title="astro.config.mjs"
fumadocs({
  components: './src/components/mdx.tsx', // [!code ++]
});
```

```tsx title="src/components/mdx.tsx"
import defaultMdxComponents from 'fumadocs-ui/mdx';
import type { MDXComponents } from 'mdx/types';

export function getMDXComponents(components?: MDXComponents) {
  return {
    ...defaultMdxComponents,
    ...components,
  } satisfies MDXComponents;
}

export default getMDXComponents();
```

Without it, pages use the default components of Fumadocs UI. Add your own React components to the object:

```tsx title="src/components/mdx.tsx"
import { ProductCard } from '@/components/product-card'; // [!code ++]

export function getMDXComponents(components?: MDXComponents) {
  return {
    ...defaultMdxComponents,
    ProductCard, // [!code ++]
    ...components,
  } satisfies MDXComponents;
}
```

### How Content Renders

The content of a page renders as one React island. Its components share a React tree and hydrate like on other frameworks: tabs, accordions, copy buttons and JSX props like `icon={<Icon />}` work.

Some parts are rendered by Astro, inside the island:

- Highlighted code.
- Images, with the image pipeline of Astro.
- Components imported in the MDX file, including Astro components. Framework components keep the rules of Astro, add `client:load` to hydrate them.
- `{expressions}`, they can't use the components of your `components` module.

The island is a React tree of its own, so:

- Props of your MDX components are serialized into the island, they must be JSON-serializable (no functions).
- It can't read the theme state of the layout, style light/dark mode with CSS (like `dark:` variants) rather than `useTheme()`.
