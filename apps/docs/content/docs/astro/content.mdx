## Pages

Each MDX file in `content/docs` is a page, with the same [conventions](/docs/page-conventions) and [Markdown features](/docs/markdown) as other Fumadocs apps.

The URLs start with the `baseUrl` of your [source](/docs/astro/manual-installation#source-files). With the [`base`](https://docs.astro.build/en/reference/configuration-reference/#base) of Astro, include it in `baseUrl`, like `/my-base/docs`.

Docs pages are generated at build time, or rendered on request with [`output: 'server'`](https://docs.astro.build/en/guides/on-demand-rendering/) like other Astro pages.

### Frontmatter

```mdx title="content/docs/setup.mdx"
---
title: Setup
description: Install the app.
# use all available width
full: true
---
```

To add fields of your own, extend the schema of the collection:

```ts title="src/content.config.ts"
import { defineCollection } from 'astro:content';
import { pageSchema } from 'fumadocs-core/source/schema';
import { metaLoader, pageLoader } from '@fumadocs/astro/loaders';
import { z } from 'astro/zod';

export const collections = {
  docs: defineCollection({
    loader: pageLoader(),
    schema: pageSchema.extend({ draft: z.boolean().optional() }), // [!code ++]
  }),
  meta: defineCollection({ loader: metaLoader() }),
};
```

## MDX Components

Pages render with the components of [Fumadocs UI](/docs/ui) by default. To use your own, create a module whose default export is the MDX components:

```tsx tab="src/components/mdx.tsx"
import defaultMdxComponents from 'fumadocs-ui/mdx';
import type { MDXComponents } from 'mdx/types';

export function getMDXComponents(components?: MDXComponents) {
  return {
    ...defaultMdxComponents,
    ...components,
  } satisfies MDXComponents;
}

export default getMDXComponents();
```

```js tab="astro.config.mjs"
fumadocs({
  components: './src/components/mdx.tsx', // [!code ++]
});
```

### Rendering

The content of each page renders as one React island, so components share a React tree and hydrate like on other frameworks: code tabs, accordions, and JSX props like `icon={<Icon />}` work.

Parts that React can't render are rendered by Astro, inside the island:

- Highlighted code blocks.
- Images, with the image pipeline of Astro.
- Components imported in the MDX file, Astro components included. Add `client:load` to hydrate framework components.
- `{expressions}`, they can't use the components of your MDX components module.

Props of your MDX components are serialized into the island, they must be JSON-serializable. As the island is a React tree of its own, use the `wrapper` component to add providers to it.

Components outside the docs page island, like [Graph View](/docs/ui/components/graph-view), need a framework provider of their own:

```tsx tab="src/components/graph.tsx"
import { AstroProvider } from 'fumadocs-core/framework/astro';
import { navigate } from 'astro:transitions/client';
import { GraphView, type GraphViewProps } from './graph-view';

export function Graph({ pathname, ...props }: GraphViewProps & { pathname: string }) {
  return (
    <AstroProvider pathname={pathname} navigate={navigate}>
      <GraphView {...props} />
    </AstroProvider>
  );
}
```

```astro tab="src/components/Graph.astro"
---
import { Graph } from './graph';
import { buildGraph } from '@/lib/build-graph';
---

<Graph client:load graph={buildGraph()} pathname={Astro.url.pathname} />
```

### Heavy Components

Every page loads your MDX components module. Add large components used on a few pages, like `<OpenAPIPage />`, with `lazy()` so other pages don't load them:

```tsx title="src/components/mdx.tsx"
import { lazy } from 'react';

const OpenAPIPage = lazy(() => import('./api-page').then((mod) => ({ default: mod.OpenAPIPage })));

export function getMDXComponents(components?: MDXComponents) {
  return {
    ...defaultMdxComponents,
    OpenAPIPage, // [!code ++]
    ...components,
  } satisfies MDXComponents;
}
```

## Markdown

Configure the Markdown of your docs on the integration, the `markdown` config of Astro only applies to other Markdown files:

```js title="astro.config.mjs"
import { remarkMdxMermaid } from '@fumadocs/satteri/remark-mdx-mermaid';

fumadocs({
  // syntax highlighting
  rehypeCodeOptions: {
    themes: { light: 'catppuccin-latte', dark: 'catppuccin-mocha' },
  },
  // Sätteri plugins, from `@fumadocs/satteri` or your own
  mdastPlugins: [remarkMdxMermaid()],
});
```

The built-in plugins take the same options as on [Fumadocs MDX](/docs/mdx/mdx#customize-built-in-plugins), see [Configuration](/docs/astro/configuration#integration) for all options. [Include](/docs/mdx/include) and [heading IDs](/docs/headless/mdx/headings) are enabled by default.

For [Math](/docs/markdown/math), add `@import 'katex/dist/katex.css';` to `src/styles/global.css`.

## Collections

The integration processes the MDX files of `content/docs` by default. To add another directory, like a blog, add it to `collections`:

```js tab="astro.config.mjs"
fumadocs({
  collections: {
    docs: { dir: 'content/docs' },
    blog: { dir: 'content/blog' }, // [!code ++]
  },
});
```

```ts tab="src/content.config.ts"
export const collections = {
  // ...
  blog: defineCollection({ loader: pageLoader('blog') }), // [!code ++]
};
```

Each collection takes the options of the integration, like its own `components`. For the pages of a blog, see [Blog](/docs/integrations/blog).

Pages from other content sources join by passing a [record of sources](/docs/headless/source-api/source#multiple-sources) to `loader()`, like the pages generated by [OpenAPI](/docs/astro/openapi).

## Other Content Sources

[Content sources](/docs/integrations/content) other than MDX files work as your `source`. Pass its loader, for example with Local Markdown:

```ts title="src/fumadocs.config.ts"
import { defineConfig } from '@fumadocs/astro/config';
import { loader } from 'fumadocs-core/source';
import { localMd } from '@fumadocs/local-md';

const docs = localMd({ dir: 'content/docs' });

export default defineConfig({
  source: loader(await docs.staticSource(), { baseUrl: '/docs' }), // [!code ++]
});
```

[Local Markdown](/docs/integrations/content/local-md), [Local HTML](/docs/integrations/content/local-html), [Obsidian](/docs/integrations/content/obsidian) and [Python](/docs/integrations/content/python) need no setup. [Notion](/docs/integrations/content/notion) and [Sanity](/docs/integrations/content/sanity) render with a plugin, see [Plugins](/docs/astro/plugins).

With the `dynamicLoader()` of a source guide, pass `await getSource()`.

The pages render with your [MDX components](#mdx-components), with relative links resolved. Add the components of a source to them, like `fumadocs-obsidian/ui`, so they render and hydrate.
