The `remarkLLMs` plugin exports the Markdown of a document as `_markdown`, for LLMs. It keeps the Markdown you wrote. See [Stringification](/docs/headless/mdx/stringification) for how it's generated.

```mdx tab="Input"
import { Callout } from 'fumadocs-ui/components/callout';

## Getting Started

<Callout>Hello **world**.</Callout>
```

```md tab="Output"
## Getting Started [#getting-started]

<Callout>Hello **world**.</Callout>
```

ESM is removed, headings get their IDs (see `headingIds`), and included content is expanded with Fumadocs MDX.

## Usage

`remarkLLMs` is a remark plugin. Enable it in Fumadocs MDX with `includeProcessedMarkdown`, on both unified and Sätteri:

```ts title="source.config.ts"
import { defineDocs } from 'fumadocs-mdx/config';

export const docs = defineDocs({
  docs: {
    postprocess: {
      // `true`, or the options of `remarkLLMs`
      includeProcessedMarkdown: true,
    },
  },
});
```

Read it from your pages:

```ts
const markdown = await page.data.getText('processed');
```

## Images

Images beside your pages, imported by [Remark Image](/docs/headless/mdx/remark-image), get the URLs your bundler serves them at:

```md tab="Input"
![How a calculation flows](./flow.png)
```

```md tab="Output"
![How a calculation flows](/assets/flow-Dxg6sAyC.png)
```

Images in the public directory keep their address. Vite inlines images smaller than [`build.assetsInlineLimit`](https://vite.dev/config/build-options#build-assetsinlinelimit) as `data:` URLs.

## JSX Elements

With [runtime analysis](#analysis), JSX elements render with the same components as the page: the components that the file imports or declares, and your MDX components for the other names. Pass your MDX components to `getText()`:

```tsx
import { getMDXComponents } from '@/components/mdx';

const markdown = await page.data.getText('processed', {
  components: getMDXComponents(),
});
```

A component defines its Markdown form with [`asMarkdown()`](/docs/headless/utils/markdown#asmarkdown). Components that don't are kept as JSX. To remove elements, or replace them with their children, use `filterElement` (unavailable on Sätteri).

### Placeholders

To render JSX elements yourself, list them as placeholders:

```ts
import type { LLMsOptions } from 'fumadocs-core/mdx-plugins/remark-llms';

const llmsOptions: LLMsOptions = {
  mdxAsPlaceholder: ['Callout'],
};
```

Then render them, from runtime data if needed:

```ts
import { renderPlaceholder } from 'fumadocs-core/mdx-plugins/remark-llms.runtime';

const markdown = await renderPlaceholder(await page.data.getText('processed'), {
  // `children` is the Markdown of its content
  Callout: ({ attributes, children }) => `> **${attributes.title}**\n>\n> ${children}`,
});
```

On Sätteri, `mdxAsPlaceholder` is unavailable.

## Analysis

The `analysis` option sets whether the Markdown renders for the props of the content:

- `runtime`: `_markdown` is a component, rendered into Markdown with [`renderToMarkdown()`](/docs/headless/utils/markdown). It only includes the [`<show>`](/docs/markdown#show) branches that show. Expressions render as their values, and JSX elements render with your components.
- `static` (default): `_markdown` is a string. It includes every branch, and JSX elements and expressions keep their source text.

Fumadocs MDX passes the [`analysis`](/docs/mdx/collections#analysis) of the collection, `runtime` by default, and `getText('processed')` renders the Markdown for the props of each page. `@fumadocs/astro` always uses `runtime`.
