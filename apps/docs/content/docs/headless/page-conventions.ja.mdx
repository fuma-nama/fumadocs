---

> このガイドは、**Fumadocs MDX** など、`loader()` API を使用するコンテンツソースにのみ適用されます。

## 概要 [#overview]

Fumadocs は [`loader()`](/docs/headless/source-api) を使用して、コンテンツディレクトリから **ページスラッグ** と **ページツリー** (サイドバーの項目) を生成します。
ルーティング機能は、お使いの React フレームワークが担います。

ファイルシステムベースのルーティングと同じように、フォルダーとページを定義できます。

<Files>
  <Folder name="content/docs (コンテンツディレクトリ)" defaultOpen>
    <File name="index.mdx" />

    <File name="getting-started.mdx" />
  </Folder>
</Files>

出力をさらにカスタマイズしたい場合は、[ローダープラグイン](/docs/headless/source-api/plugins)を使用できます。

## ファイル [#file]

[MDX](https://mdxjs.com) &amp; Markdown ファイルでは、フロントマターでページ情報をカスタマイズできます。

```mdx
---
title: My Page
description: Best document ever
icon: House
---

## Learn More
```

Fumadocs は、以下のプロパティをもとにページツリーを構築します。

| 名前            | 説明                            |
| ------------- | ----------------------------- |
| `title`       | ページのタイトル                      |
| `description` | ページの説明                        |
| `icon`        | アイコン名。[アイコン](#icons)を参照してください |

<Callout title="補足">
  ページ情報は、**Fumadocs MDX** などのコンテンツソースから提供されます。

  Fumadocs MDX では、[`schema`](/docs/mdx/collections#schema-1) オプションを指定してフロントマターのスキーマをカスタマイズできます。
</Callout>

### スラッグ [#slugs]

ページのスラッグは、そのファイルパスから生成されます。

| パス(コンテンツフォルダーからの相対パス) | スラッグ              |
| --------------------- | ----------------- |
| `./dir/page.mdx`      | `['dir', 'page']` |
| `./dir/index.mdx`     | `['dir']`         |

## フォルダー [#folder]

複数のページをフォルダーに入れるとグループ化できます。フォルダーをカスタマイズするには、[メタファイル](#meta)を作成してください。

ページが `index` だけのフォルダーは、メタファイルがない限り、ページツリー上ではページアイテムになります。
たとえば、`guide/index.mdx` は `guide.mdx` と同じようにサイドバーに表示されます。

### フォルダーグループ [#folder-group]

デフォルトでは、ファイルをフォルダーに入れるとそのファイルの slugs が変わります。
フォルダー名を括弧で囲むと、子ファイルの slugs に影響を与えずに済みます。

| パス (コンテンツフォルダーからの相対パス)    | slugs      |
| ------------------------- | ---------- |
| `./(group-name)/page.mdx` | `['page']` |

### ルートフォルダー [#root-folder]

フォルダーをルートフォルダーとして指定します。表示されるのは、開いているルートフォルダー内の項目のみです。

```json title="meta.json"
{
  "title": "Name of Folder",
  "description": "The description of root folder (optional)",
  "root": true
}
```

たとえば、ルートフォルダー `framework` を開いている場合、他のフォルダー(例: `headless`)はサイドバーやその他のナビゲーション要素に表示されません。

<Files>
  <Folder name="framework" defaultOpen>
    <File name="index.mdx" />

    <File name="current-page.mdx" className="text-fd-primary! bg-fd-primary/10!" />

    <File name="other-pages.mdx" />
  </Folder>

  <Folder name="headless (hidden)" className="opacity-50" disabled defaultOpen>
    <File name="my-page.mdx" />
  </Folder>
</Files>

<Callout title="Fumadocs UI">
  Fumadocs UI では、ルートフォルダーが[レイアウトタブ](/docs/ui/layouts/docs#layout-tabs)としてレンダリングされ、ユーザーはそれらを切り替えられます。
</Callout>

### ルートタイプ [#root-type]

`root` には文字列も指定でき、これはルートフォルダーの**タイプ**を表します。
同じ親スコープ内にある同じタイプのルートフォルダーは、同じドキュメントの異なるバージョンのように、互いに切り替え可能なものとして扱われます。

<Files>
  <Folder name="v1" defaultOpen>
    <File name="meta.json" />

    <File name="index.mdx" />

    <File name="guide.mdx" className="text-fd-primary! bg-fd-primary/10!" />
  </Folder>

  <Folder name="v2" defaultOpen>
    <File name="meta.json" />

    <File name="index.mdx" />

    <File name="guide.mdx" className="text-fd-primary! bg-fd-primary/10!" />
  </Folder>
</Files>

```json tab="v1/meta.json"
{
  "title": "1.0.0",
  "root": "version"
}
```

```json tab="v2/meta.json"
{
  "title": "2.0.0",
  "root": "version"
}
```

`root: true` は単にデフォルトのタイプで、タブとして表示されます。

同じタイプの別のルートフォルダーに切り替えると、ページはその**構造的射影**、つまりルートフォルダーからの相対パスが同じページに対応付けられます。

| ページ                   | `v2` での射影                                    |
| --------------------- | -------------------------------------------- |
| `v1/guide.mdx`        | `v2/guide.mdx`                               |
| `v1/python/guide.mdx` | `v2/python/guide.mdx`(ネストされたルートフォルダーは維持されます) |

<Callout title="Fumadocs UI">
  Fumadocs UI は、現在のページのパス上にある各ルートフォルダーに対して[ドロップダウン](/docs/ui/layouts/docs#tabs-groups)をレンダリングし、同じタイプのルートフォルダー間で切り替えられるようにします。完全な例については[バージョニング](/docs/navigation#versioning)を参照してください。
</Callout>

## Meta [#meta]

フォルダー内に `meta.json` ファイルを作成すると、フォルダーをカスタマイズできます。

```json tab="meta.json"
{
  "title": "Display Name",
  "icon": "MyIcon",
  "pages": ["index", "getting-started"],
  "defaultOpen": true
}
```

```ts tab="meta.ts"
export default {
  title: 'Display Name',
  icon: 'MyIcon',
  pages: ['index', 'getting-started'],
  defaultOpen: true,
};
```

コンテンツソースが対応している場合は、メタファイルをコード (`meta.ts` または `meta.js`) で記述し、データをデフォルトエクスポートとして指定できます。

| 名前            | 説明                                   |
| ------------- | ------------------------------------ |
| `title`       | 表示名                                  |
| `icon`        | アイコン名。[アイコン](#icons)を参照してください        |
| `defaultOpen` | フォルダーをデフォルトで開く                       |
| `collapsible` | フォルダーの内容を折りたたみ可能にする (デフォルト: `true`)  |
| `pages`       | フォルダー内の項目 (後述)                       |
| `pagesIndex`  | インデックス項目 (後述)                        |

### ページ [#pages]

フォルダー内のアイテムはデフォルトでアルファベット順に並びます。`pages` を使用すると、アイテムを追加したり、表示順を制御したりできます。

```json title="meta.json"
{
  "pages": ["index", "getting-started"]
}
```

> 指定した場合、`pages` に記載されていないアイテムは含まれません。

| 種類                | 構文                                                                 | 説明                                                          |
| ----------------- | ------------------------------------------------------------------ | ----------------------------------------------------------- |
| **パス**            | `./path/to/page`                                                   | ページまたはフォルダーへのパスです。                                          |
| **セパレーター**        | `---Label---`<br />`---[Icon]Label---`                             | 2つのセクションの間の区切りです(アイコン対応)。                                   |
| **リンク**           | `[Text](url)`<br />`[Icon][Text](url)`<br />`external:[Text](url)` | リンクを挿入します(アイコン対応)。<br />`external:` プレフィックスを付けると外部リンクになります。 |
| **Rest**          | `...`                                                              | 残りのページを含めます(アルファベット順)。                                      |
| **Reversed Rest** | `z...a`                                                            | **Rest** アイテムの逆順版です。                                        |
| **Extract**       | `...folder`                                                        | フォルダー内のアイテムを展開します。                                          |
| **Except**        | `!item`                                                            | `...` または `z...a` からアイテムを除外します。                             |

```json title="meta.json"
{
  "pages": [
    "components",
    "---My Separator---",
    "...folder",
    "...",
    "!file",
    "!otherFolder",
    "[Vercel](https://vercel.com)",
    "[Triangle][Vercel](https://vercel.com)"
  ]
}
```

<Callout type="warn" title="URL の重複は不可">
  同じページ URL をページツリー全体で複数回使用することはできません。
  同じ理由から、ページ項目の重複も許可されていません。

  これは意図的な仕様です。これにより、Fumadocs は現在のパス名だけを基にアクティブなツリー項目を特定できます。
</Callout>

### フォルダーのインデックス [#folder-index]

フォルダーにインデックス項目がある場合、そのフォルダーはクリック可能になり、クリックするとインデックス項目に移動します。

デフォルトでは、各フォルダー内の `index` ファイルがインデックス項目になります。フォルダーのインデックス項目は個別に指定することもでき、**パス**または**リンク**を指定できます。

```json tab="meta.json (Path)"
{
  // フォルダー内に "overview.mdx" ファイルがあるものとします
  "pagesIndex": "overview"
}
```

```json tab="meta.json (Link)"
{
  "pagesIndex": "[Example](https://example.com)"
}
```

## アイコン [#icons]

Fumadocs にはアイコンライブラリが含まれていないため、アイコン名をランタイムに JSX 要素へ変換し、コンポーネントとしてレンダリングする必要があります。

`loader()` に [`icon` ハンドラー](/docs/headless/source-api#icons)を追加できます。

## i18n ルーティング [#i18n-routing]

i18n ルーティングのスタイルは、用途に応じて定義できます。

```ts title="lib/i18n.ts"
import type { I18nConfig } from 'fumadocs-core/i18n';

export const i18n: I18nConfig = {
  // デフォルト
  parser: 'dot',
  // または
  parser: 'dir',
};
```

<Tabs items={['dot', 'dir']}>
  <Tab>
    ファイル名の末尾に `.{locale}` を付けると、言語ごとの Markdown/meta ファイルを追加できます。例:

    <Files>
      <Folder name="content/docs" defaultOpen>
        <File name="meta.json" />

        <File name="meta.cn.json" />

        <File name="get-started.mdx" />

        <File name="get-started.cn.mdx" />
      </Folder>
    </Files>

    デフォルトのロケールでは、ロケールコードを省略できます。
  </Tab>

  <Tab>
    すべてのコンテンツファイルを言語ごとのフォルダーに分けて配置します。

    <Files>
      <Folder name="content/docs" defaultOpen>
        <Folder name="en" defaultOpen>
          <File name="meta.json" />

          <File name="get-started.mdx" />
        </Folder>

        <Folder name="cn" defaultOpen>
          <File name="meta.json" />

          <File name="get-started.mdx" />
        </Folder>
      </Folder>
    </Files>
  </Tab>
</Tabs>

## パスパラメーター [#path-params]

`[name]` という名前のフォルダーは、パラメーターの値ごとに生成されます。値はそのフォルダーのメタファイルにある `staticParams` に列挙してください。

<Files>
  <Folder name="content/docs" defaultOpen>
    <Folder name="[framework]" defaultOpen>
      <File name="meta.json" />

      <File name="deploy.mdx" />
    </Folder>
  </Folder>
</Files>

```json title="[framework]/meta.json"
{
  "title": "Framework",
  "staticParams": [{ "framework": "waku" }, { "framework": "astro" }]
}
```

| パス(コンテンツフォルダーからの相対パス)      | slugs                                       |
| -------------------------- | ------------------------------------------- |
| `./[framework]/deploy.mdx` | `['waku', 'deploy']`, `['astro', 'deploy']` |

meta ファイルは、生成されるすべてのフォルダーに適用されます。ページは params を [props](/docs/markdown#props) として受け取るほか、`loader()` 経由で `page.params` としても受け取ります。

`meta.ts` では、代わりに params を受け取る関数をエクスポートし、あわせて `staticParams` を名前付きエクスポートとして定義することもできます。

```ts title="[framework]/meta.ts"
const names = { waku: 'Waku', astro: 'Astro' };

export const staticParams = [{ framework: 'waku' }, { framework: 'astro' }];

export default ({ framework }: { framework: keyof typeof names }) => ({
  title: names[framework],
});
```

<Callout title="補足">
  `[name]` フォルダーは、その値がどこにも列挙されていない場合、通常のフォルダーとして扱われます。
</Callout>

### ページの params [#page-params]

ページのフロントマターにも `staticParams` を記述できます。そのページのフォルダーにも記述されている場合、ページは両方に共通する値に対してのみ生成されます。

```mdx title="[framework]/fumadocs-mdx.mdx"
---
title: Fumadocs MDX
staticParams:
  - framework: waku
---
```

### 静的パス [#static-paths]

固定のパスに配置したファイルは、自動生成されるファイルよりも優先されます。たとえば、`astro/deploy.mdx` は `[framework]/deploy.mdx` から生成される `astro` ページを置き換えます。メタファイルについても同様です。

### ローカライズされたページ [#localized-pages]

[i18n](#i18n-routing) を使用する場合、各ロケールのファイルはそのフォールバックロケールのファイルよりも優先されます。`/cn/docs/astro/deploy` の場合は、次のうち最初に見つかったファイルが使用されます。

1. `astro/deploy.cn.mdx`
2. `[framework]/deploy.cn.mdx`
3. `astro/deploy.mdx`
4. `[framework]/deploy.mdx`

ローカライズされたページは、まず `meta.cn.json` から `staticParams` を読み取ります。`dir` パーサーを使用する場合は、言語ごとのフォルダーにそれぞれ独自の値を記述します。
