## Getting Started

Before continuing, make sure to configure:

- Astro 7.
- Tailwind CSS 4.

Docs are MDX files loaded by Astro content collections. `@fumadocs/astro` adds the Markdown features of Fumadocs to them, and Fumadocs UI renders in React islands.

### Installation

```npm
npm i fumadocs-core fumadocs-ui @fumadocs/astro @astrojs/react react react-dom @types/mdx
```

## Rendering

With `components`, the MDX content of each page renders as one React island (`client:load`). Its components share a React tree and hydrate like on other frameworks: interactive code blocks, tabs, accordions and heading anchors work, and so do JSX props like `icon={<Icon />}`.

Parts that React can't render are rendered by Astro, inside the island:

- Highlighted code.
- Images, with the image pipeline of Astro.
- Components imported in the MDX file, including Astro components. Framework components keep the rules of Astro, add `client:load` to hydrate them.
- `{expressions}`, they can't use the components of your `components` module.

Props of the components in your `components` module are serialized into the island, they must be JSON-serializable (no functions).

The island is a React tree of its own, providers of your layout don't reach it. `wrapper` receives the props of `<Content />`, use it to add providers, like for [Internationalization](/docs/internationalization/astro). The theme state isn't shared either, style light/dark mode with CSS (e.g. `dark:` variants) rather than `useTheme()`.

Without `components`, the content renders as Astro MDX, without React. Pass components to `<Content />` like other Astro content:

```astro
<Content components={{ h2: Heading }} />
```

## Options

```js title="astro.config.mjs"
fumadocs({
  // module whose default export is the MDX components
  components: './src/components/mdx.tsx',
  // enable `getText('processed')` on pages
  includeProcessedMarkdown: false,
  // content directories, relative to the project root
  collections: {
    docs: { dir: 'content/docs' },
  },
});
```

The values above are the defaults, except `components`. Fumadocs only processes the MDX files of `collections`, other Markdown of your project is left to Astro.

The integration adds `@astrojs/react` and `@astrojs/mdx` with their default options, add them to `integrations` yourself to configure them.

### Collections

Collections take the options above, the options of the integration are their defaults. For example, a blog with its own MDX components:

```js title="astro.config.mjs"
fumadocs({
  components: './src/components/mdx.tsx',
  collections: {
    docs: { dir: 'content/docs' },
    // [!code ++]
    blog: { dir: 'content/blog', components: './src/components/blog-mdx.tsx' },
  },
});
```

Load it with `pageLoader('blog')`, and create a source with `toFumadocsSource(await getCollection('blog'))`.

### Plugins

Add Sätteri plugins to docs with `mdastPlugins` and `hastPlugins`, as an array or a function receiving the default plugins. For example, to render `mermaid` code blocks with the [`Mermaid` component](/docs/markdown/mermaid) of your MDX components:

```npm
npm i @fumadocs/satteri
```

```js title="astro.config.mjs"
import { remarkMdxMermaid } from '@fumadocs/satteri/remark-mdx-mermaid';

fumadocs({
  mdastPlugins: [remarkMdxMermaid()],
});
```

They only run on docs, while plugins of the `satteri()` processor of Astro apply to every Markdown file.

The built-in plugins take the same options as [Fumadocs MDX](/docs/mdx/mdx#customize-built-in-plugins): `remarkHeadingOptions`, `remarkCodeTabOptions`, `remarkNpmOptions`, `remarkStructureOptions`, `rehypeCodeOptions` and `rehypeKatexOptions`.

Fumadocs highlights the code blocks of docs, configure it with `rehypeCodeOptions`. The `markdown.shikiConfig` of Astro only applies to other Markdown.

```js title="astro.config.mjs"
fumadocs({
  rehypeCodeOptions: {
    themes: { light: 'catppuccin-latte', dark: 'catppuccin-mocha' },
  },
});
```

## Page Data

Pages of `toFumadocsSource()` have:

```ts
// the MDX content, table of contents and structured data (for search)
const { body, toc, structuredData } = await page.data.load();

// structured data only
await page.data.structuredData();

// the source file, or the Markdown processed by Fumadocs (requires `includeProcessedMarkdown`)
await page.data.getText('raw');
await page.data.getText('processed');
```
