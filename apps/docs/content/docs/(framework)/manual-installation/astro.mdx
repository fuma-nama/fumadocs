## Getting Started

Before continuing, make sure to configure:

- Astro 7.4 on Node.js 22.23.4 or later.
- Sätteri as the Markdown processor, the default of Astro 7.
- Tailwind CSS 4.

Docs are MDX files loaded by Astro content collections. `@fumadocs/astro` adds the Markdown features of Fumadocs to them, and Fumadocs UI renders in React islands. You write the routes, or let [Fumapress on Astro](https://press.fumadocs.dev/docs/astro) manage them with plugins like `llms.txt` and OG images.

### Installation

```npm
npm i fumadocs-core fumadocs-ui @fumadocs/astro @astrojs/react react react-dom @types/mdx
```

## Rendering

With `components`, the MDX content of each page renders as one React island (`client:load`). Its components share a React tree and hydrate like on other frameworks: interactive code blocks, tabs, accordions and heading anchors work, and so do JSX props like `icon={<Icon />}`.

Parts that React can't render are rendered by Astro, inside the island:

- Highlighted code.
- Images, with the image pipeline of Astro.
- Components imported in the MDX file, including Astro components. Framework components keep the rules of Astro, add `client:load` to hydrate them.
- `{expressions}`, they can't use the components of your `components` module.

Props of the components in your `components` module are serialized into the island like the props of Astro islands: dates and maps work, functions don't.

The island is a React tree of its own, providers of your layout don't reach it. `wrapper` receives the props of `<Content />`, use it to add providers, like for [Internationalization](/docs/internationalization/astro). The theme state isn't shared either, style light/dark mode with CSS (e.g. `dark:` variants) rather than `useTheme()`.

Without `components`, the content renders as Astro MDX, without React. Pass components to `<Content />` like other Astro content:

```astro
<Content components={{ h2: Heading }} />
```

## Options

```js title="astro.config.mjs"
fumadocs({
  // module whose default export is the MDX components
  components: './src/components/mdx.tsx',
  // enable `getText('processed')` on pages
  includeProcessedMarkdown: false,
  // add the links of pages to `page.data.extractedReferences`
  extractLinkReferences: false,
  // add the date of the last commit to `page.data.lastModified`
  lastModified: false,
  // content directories, relative to the project root
  collections: {
    docs: { dir: 'content/docs' },
  },
});
```

The values above are the defaults, except `components`. Fumadocs only processes the MDX files of `collections`, other Markdown of your project is left to Astro.

The integration adds `@astrojs/react` and `@astrojs/mdx` with their default options, add them to `integrations` yourself to configure them.

`extractLinkReferences` is for the [Graph View](/docs/ui/components/graph-view). `lastModified` reads the git history at build time: uncommitted pages have no date, and a shallow clone (common in CI) gives every page the date of the latest commit.

### Processed Markdown

`getText('processed')` returns MDX components as JSX by default. With the function output, they render with your MDX components, which define their Markdown form with [`asMarkdown()`](/docs/headless/mdx/remark-llms#output):

```js title="astro.config.mjs"
fumadocs({
  includeProcessedMarkdown: { output: 'function' },
});
```

### Collections

Collections take the options above, the options of the integration are their defaults. For example, a blog with its own MDX components:

```js title="astro.config.mjs"
fumadocs({
  components: './src/components/mdx.tsx',
  collections: {
    docs: { dir: 'content/docs' },
    // [!code ++]
    blog: { dir: 'content/blog', components: './src/components/blog-mdx.tsx' },
  },
});
```

Load it with `pageLoader('blog')`, and create a source with `toFumadocsSource(await getCollection('blog'))`.

### Plugins

Add Sätteri plugins to docs with `mdastPlugins` and `hastPlugins`, as an array or a function receiving the default plugins. For example, to render `mermaid` code blocks with the [`Mermaid` component](/docs/markdown/mermaid) of your MDX components:

```npm
npm i @fumadocs/satteri
```

```js title="astro.config.mjs"
import { remarkMdxMermaid } from '@fumadocs/satteri/remark-mdx-mermaid';

fumadocs({
  mdastPlugins: [remarkMdxMermaid()],
});
```

They only run on docs, while plugins of the `satteri()` processor of Astro apply to every Markdown file.

The built-in plugins take the same options as [Fumadocs MDX](/docs/mdx/mdx#customize-built-in-plugins): `remarkHeadingOptions`, `remarkCodeTabOptions`, `remarkNpmOptions`, `remarkStructureOptions`, `rehypeCodeOptions` and `rehypeKatexOptions`.

Fumadocs highlights the code blocks of docs, configure it with `rehypeCodeOptions`. The `markdown.shikiConfig` of Astro only applies to other Markdown.

```js title="astro.config.mjs"
fumadocs({
  rehypeCodeOptions: {
    themes: { light: 'catppuccin-latte', dark: 'catppuccin-mocha' },
  },
});
```

## Page Data

Pages of `toFumadocsSource()` have:

```ts
// the MDX content, table of contents and structured data (for search)
const { body, toc, structuredData } = await page.data.load();

// structured data only
await page.data.structuredData();

// the source file, or the Markdown processed by Fumadocs (requires `includeProcessedMarkdown`)
await page.data.getText('raw');
await page.data.getText('processed');

// with `extractLinkReferences` and `lastModified`
page.data.extractedReferences;
page.data.lastModified;
```

### Page Markdown

Serve the processed Markdown of pages at `<page>.md` for AI agents, like `/docs/test.md` and `/docs/index.md` for the root page. It requires `includeProcessedMarkdown`:

<include cwd meta='tab="src/pages/docs/[...slug].md.ts"'>
  ../../examples/astro/src/pages/docs/[...slug].md.ts
</include>

```ts tab="src/lib/source.ts"
import { llms, loader } from 'fumadocs-core/source'; // [!code highlight]

export const source = loader({
  // ...
});

// [!code ++:5]
export const docsLlms = llms(source, {
  renderPage: async (page) => `# ${page.data.title} (${page.url})

${await page.data.getText('processed')}`,
});
```

`docsLlms` also renders `llms.txt`, as in [Docs for LLM](/docs/integrations/llms#docsllms).

## Sitemap

Use [`@astrojs/sitemap`](https://docs.astro.build/en/guides/integrations-guide/sitemap) with `serializeSitemap` as its `serialize` option. It requires [`site`](https://docs.astro.build/en/reference/configuration-reference/#site):

```js title="astro.config.mjs"
import { defineConfig } from 'astro/config';
import fumadocs, { serializeSitemap } from '@fumadocs/astro'; // [!code ++]
import sitemap from '@astrojs/sitemap';

export default defineConfig({
  site: 'https://example.com', // [!code ++]
  integrations: [
    fumadocs({ components: './src/components/mdx.tsx' }),
    sitemap({ serialize: serializeSitemap }), // [!code ++]
  ],
});
```

It reads the `<head>` of each built page:

- `lastmod` from `<meta property="article:modified_time">`.
- Language alternates from `<link rel="alternate" hreflang>`.
- Pages with `<meta name="robots" content="noindex">` are left out.

For example, render the date of [`lastModified`](#options) in your layout:

```astro tab="src/layouts/Layout.astro"
---
interface Props {
  title: string;
  description?: string;
  lastModified?: Date; // [!code ++]
}

const { title, description, lastModified } = Astro.props;
---

<head>
  <!-- ... -->
  <!-- [!code ++:3] -->
  {lastModified && (
    <meta property="article:modified_time" content={lastModified.toISOString()} />
  )}
</head>
```

```astro tab="src/pages/docs/[...slug].astro"
---
// ...
// [!code word:lastModified={page.data.lastModified}]
---

<Layout
  title={page.data.title}
  description={page.data.description}
  lastModified={page.data.lastModified}
>
  <!-- ... -->
</Layout>
```
