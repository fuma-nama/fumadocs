## Overview

Fumadocs AsyncAPI uses a `<AsyncAPIPage />` component to render page contents, it should be a client component.

```tsx title="components/api-page.tsx"
'use client';
import { createAsyncAPIPage } from '@fumadocs/asyncapi/ui';

export const AsyncAPIPage = createAsyncAPIPage({
  // config
});
```

### Custom Layout

You can customize how the sections of operations are laid out.

```tsx title="components/api-page.tsx"
'use client';
import { createAsyncAPIPage } from '@fumadocs/asyncapi/ui';

export const AsyncAPIPage = createAsyncAPIPage({
  content: {
    renderOperationLayout(slots) {
      return (
        <div className="flex flex-col gap-6">
          {slots.header}
          {slots.connection}
          {slots.description}
          {slots.parameters}
          {slots.messages}
        </div>
      );
    },
  },
});
```

| Slot          | Renders                                                                   |
| ------------- | ------------------------------------------------------------------------- |
| `header`      | the title, on pages with several operations                               |
| `connection`  | which way messages go, the server and channel address, and the playground |
| `description` | the descriptions of operation and its channel, and external documentation |
| `authSchemes` | security schemes of the server and operation                              |
| `parameters`  | address parameters, and the query and headers of WebSocket connections    |
| `messages`    | the messages, with their payload, headers, examples and correlation ID    |
| `reply`       | the reply of a request                                                    |
| `bindings`    | protocol details of the selected server                                   |

### Direction of Messages

AsyncAPI describes an application with `send` and `receive` actions. Pages flip them for readers, who talk to the application: `send` is shown as **Receive**, and `receive` as **Send**. The sidebar shows them as an arrow into or out of a phone.

### Playground

Operations on WebSocket servers (`ws` and `wss`) can be tried in a playground: readers connect with the address parameters, query and API keys, send messages from their examples, and see the messages they receive.

<Callout title="Browser limits">
  Browsers can't send headers or cookies of other sites with WebSocket connections, only credentials
  in the query are supported. Pages served over HTTPS can only connect to `wss` servers.
</Callout>

```tsx title="components/api-page.tsx"
'use client';
import { createAsyncAPIPage } from '@fumadocs/asyncapi/ui';

export const AsyncAPIPage = createAsyncAPIPage({
  playground: {
    // disable the playground
    enabled: false,
  },
});
```

### Schema UI

Customize how JSON schemas are rendered, or disable schema examples.

```tsx title="components/api-page.tsx"
'use client';
import { createAsyncAPIPage } from '@fumadocs/asyncapi/ui';

export const AsyncAPIPage = createAsyncAPIPage({
  schemaUI: {
    showExample: true,
    render(options, ctx) {
      // fully custom schema renderer
      return ctx.SchemaUI(options);
    },
  },
});
```

### TypeScript Definitions

Payloads and headers have a button to copy their TypeScript definitions, generated with [`@fumari/json-schema-ts`](https://npmjs.com/package/@fumari/json-schema-ts).

Like the schemas on pages, they leave out `readOnly` properties of messages readers send, and `writeOnly` properties of messages they receive.

```tsx title="components/api-page.tsx"
'use client';
import { createAsyncAPIPage } from '@fumadocs/asyncapi/ui';

export const AsyncAPIPage = createAsyncAPIPage({
  // or `(schema, ctx) => string | undefined` to generate your own
  generateTypeScriptDefinitions: false,
});
```

### Internationalization

Assuming you have configured [Internationalization](/docs/internationalization) at UI level:

```tsx title="layout.shared.tsx"
import { defineI18n } from 'fumadocs-core/i18n';
import { uiTranslations } from 'fumadocs-ui/i18n';
import { asyncapiTranslations } from '@fumadocs/asyncapi/i18n';

const i18n = defineI18n({
  languages: ['en', 'cn'],
  defaultLanguage: 'en',
});

export const translations = i18n
  .translations()
  .extend(uiTranslations())
  // [!code ++]
  .extend(asyncapiTranslations())
  .add({
    cn: {
      displayName: 'Chinese',
      // [!code ++]
      'Messages(operation page)': '消息',
    },
  });
```

See [Translations](/docs/ui/translations) for more details.

### Syntax Highlighting

AsyncAPI pages use Shiki for code blocks. You can customize the highlighter and themes.

```tsx title="components/api-page.tsx"
'use client';
import { createAsyncAPIPage } from '@fumadocs/asyncapi/ui';
import { defaultShikiFactory } from 'fumadocs-core/highlight/shiki/full';

export const AsyncAPIPage = createAsyncAPIPage({
  shiki: defaultShikiFactory,
  shikiOptions: {
    themes: {
      light: 'github-light',
      dark: 'github-dark',
    },
  },
});
```

### Custom Components

Override the default heading and code block components.

```tsx title="components/api-page.tsx"
'use client';
import { createAsyncAPIPage } from '@fumadocs/asyncapi/ui';

export const AsyncAPIPage = createAsyncAPIPage({
  components: {
    Heading({ id, depth, ...props }) {
      const Tag = `h${depth}` as const;
      return <Tag id={id} {...props} />;
    },
    CodeBlock({ lang, code }) {
      return <pre data-lang={lang}>{code}</pre>;
    },
  },
});
```

## Customise UI

For customisations beyond the available options, you can install the UI into your codebase with [Fumadocs CLI](/docs/cli).

### Full UI

The entire UI of API pages, built on [the headless layer](/docs/integrations/asyncapi/headless).

```npm
npx @fumadocs/cli add asyncapi/page
```

It installs `<AsyncAPIPage />` itself, your `components/api-page.tsx` is no longer needed.

```tsx title="mdx-components.tsx"
import { AsyncAPIPage } from '@/components/api-page'; // [!code --]
import { AsyncAPIPage } from '@/components/asyncapi/page'; // [!code ++]
```

### Operation

The UI of a single operation, including its channel, messages and bindings.

```npm
npx @fumadocs/cli add asyncapi/operation
```

### Playground

The WebSocket playground, built on [`usePlayground()`](/docs/integrations/asyncapi/headless#playground).

```npm
npx @fumadocs/cli add asyncapi/playground
```

```tsx title="components/api-page.tsx"
'use client';
import { createAsyncAPIPage } from '@fumadocs/asyncapi/ui';
import { Operation } from '@/components/asyncapi/operation';

export const AsyncAPIPage = createAsyncAPIPage({
  components: {
    Operation,
  },
});
```

### Schema UI

The UI of JSON schemas, shared with the other API integrations. Its state comes from [`<SchemaUIProvider />`](/docs/integrations/openapi/headless#schema-ui).

```npm
npx @fumadocs/cli add api-docs/schema
```

```tsx title="components/api-page.tsx"
'use client';
import { createAsyncAPIPage } from '@fumadocs/asyncapi/ui';
import { Schema } from '@/components/api/schema';

export const AsyncAPIPage = createAsyncAPIPage({
  components: {
    SchemaUI: Schema,
  },
});
```
