## Overview

Fumadocs GraphQL uses a `<GraphQLPage />` component to render page contents, it should be a client component.

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';

export const GraphQLPage = createGraphQLPage({
  // config
});
```

### Playground

Operation pages get a playground when you configure an endpoint: readers edit the operation or pick its fields, fill the variables in a form or as JSON, and send it with their headers.

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';

export const GraphQLPage = createGraphQLPage({
  playground: {
    url: 'https://api.example.com/graphql',
    // allow users to edit the endpoint URL (default: true)
    allowUrlEdit: false,
    // default headers of playground requests
    headers: {
      'X-Client-Name': 'docs',
    },
  },
});
```

<Callout type="warn">

Do not put secrets in `headers`, they are sent to the browser, shown in code samples, and kept in its local storage by endpoint origin.

</Callout>

Queries and mutations are sent over HTTP POST, you can replace their fetcher, e.g. to proxy requests:

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';

export const GraphQLPage = createGraphQLPage({
  playground: {
    async fetcher(request) {
      const start = performance.now();
      const res = await fetch('/api/proxy', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json', ...request.headers },
        body: JSON.stringify({ query: request.query, variables: request.variables }),
      });

      return {
        type: 'response',
        status: res.status,
        time: performance.now() - start,
        body: await res.text(),
        contentType: res.headers.get('Content-Type') ?? '',
        // optional, shown in a Headers tab
        headers: Array.from(res.headers),
      };
    },
  },
});
```

Or replace the playground UI entirely with `render`, it takes the place of the signature bar:

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';

export const GraphQLPage = createGraphQLPage({
  playground: {
    render({ kind, name, operation }) {
      return <div>my playground</div>;
    },
  },
});
```

#### Subscriptions

On subscription pages, the playground subscribes to `subscriptionUrl` and logs the events it receives. It defaults to `url` with a `ws(s)://` scheme.

| `subscriptionUrl`     | Protocol                                       |
| --------------------- | ---------------------------------------------- |
| `ws://`, `wss://`     | graphql-ws (`graphql-transport-ws`)            |
| `http://`, `https://` | GraphQL over SSE, in distinct connections mode |

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';

export const GraphQLPage = createGraphQLPage({
  playground: {
    url: 'https://api.example.com/graphql',
    // GraphQL over SSE on the same endpoint
    subscriptionUrl: 'https://api.example.com/graphql',
  },
});
```

<Callout title="Browser limits">
  Browsers can't set the headers of WebSocket connections, graphql-ws sends them in the payload of
  `connection_init` instead.
</Callout>

### Code Samples

Example requests are shown in GraphQL, or as code in cURL, JavaScript, Go, Python, Java, C# and Rust that sends them to `playground.url` (a placeholder when unset) with `playground.headers`. The playground shows the same code for the request being edited. Subscription pages show their example in GraphQL only.

Add generators with `codeUsages`, or remove the default ones:

```tsx title="components/api-page.tsx"
'use client';
import {
  createCodeUsageGeneratorRegistry,
  createGraphQLPage,
  registerDefaultCodeUsages,
} from '@fumadocs/graphql/ui';

// leave out the defaults to start from scratch
const codeUsages = registerDefaultCodeUsages(createCodeUsageGeneratorRegistry());

// the defaults: curl, js, go, python, java, csharp, rust
codeUsages.remove('java');
codeUsages.add('graphql-request', {
  label: 'graphql-request',
  lang: 'js',
  generate({ url, query, variables = {} }) {
    return `import { request } from 'graphql-request';

const data = await request(${JSON.stringify(url)}, ${JSON.stringify(query)}, ${JSON.stringify(variables)});`;
  },
});

export const GraphQLPage = createGraphQLPage({ codeUsages });
```

### Cross-linking

[Type pages](/docs/integrations/graphql/server#includeoperations--includetypes) link to each other and to operations automatically. Operation pages keep readers on the page, type names show their definition on hover.

You can also resolve the links yourself:

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';

export const GraphQLPage = createGraphQLPage({
  typeLinks(name) {
    return `/docs/types/${name}`;
  },
  operationLinks(kind, name) {
    return `/docs/${kind}/${name}`;
  },
});
```

Return `undefined` for types/operations without their own page.

### Custom Layout

You can customize how operation and type pages are laid out.

<Tabs items={['Operation', 'Type']}>

<Tab>

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';

export const GraphQLPage = createGraphQLPage({
  content: {
    renderOperationLayout(slots) {
      return (
        <div className="flex flex-col gap-6">
          {slots.header}
          {slots.playground}
          {slots.description}
          {slots.deprecated}
          {slots.directives}
          {slots.arguments}
          {slots.returns}
          {slots.example}
        </div>
      );
    },
  },
});
```

| Slot          | Renders                                                                     |
| ------------- | --------------------------------------------------------------------------- |
| `header`      | the title, on pages with several items                                      |
| `playground`  | the signature, like `QUERY customer(id: ID!): Customer`, and the playground |
| `description` | the description of operation                                                |
| `deprecated`  | the deprecation reason                                                      |
| `directives`  | directives applied to the operation                                         |
| `arguments`   | the arguments                                                               |
| `returns`     | the return type and its fields                                              |
| `example`     | the example request and response, beside the operation on wide pages        |

</Tab>

<Tab>

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';

export const GraphQLPage = createGraphQLPage({
  content: {
    renderTypeLayout(slots) {
      return (
        <div className="flex flex-col gap-6">
          {slots.header}
          {slots.definition}
          {slots.description}
          {slots.directives}
          {slots.fields}
          {slots.values}
          {slots.usages}
          {slots.sdl}
        </div>
      );
    },
  },
});
```

| Slot          | Renders                                                                   |
| ------------- | ------------------------------------------------------------------------- |
| `header`      | the name, on pages with several items                                     |
| `definition`  | the head of its SDL, like `type Order implements Node`                    |
| `description` | the description of type                                                   |
| `directives`  | directives applied to the type                                            |
| `fields`      | fields of objects, interfaces and input objects, or the members of unions |
| `values`      | values of enums                                                           |
| `usages`      | implementations, unions, and the operations and fields using the type     |
| `sdl`         | the SDL of type, beside it on wide pages                                  |

</Tab>

</Tabs>

### Schema UI

Customize how types are rendered.

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';

export const GraphQLPage = createGraphQLPage({
  schemaUI: {
    render(options, ctx) {
      // fully custom schema renderer
      return <ctx.SchemaUI {...options} />;
    },
  },
});
```

### Internationalization

Assuming you have configured [Internationalization](/docs/internationalization) at UI level:

```tsx title="layout.shared.tsx"
import { defineI18n } from 'fumadocs-core/i18n';
import { uiTranslations } from 'fumadocs-ui/i18n';
import { graphqlTranslations } from '@fumadocs/graphql/i18n';

const i18n = defineI18n({
  languages: ['en', 'cn'],
  defaultLanguage: 'en',
});

export const translations = i18n
  .translations()
  .extend(uiTranslations())
  // [!code ++]
  .extend(graphqlTranslations())
  .add({
    cn: {
      displayName: 'Chinese',
      // [!code ++]
      'Arguments(operation page)': '参数',
    },
  });
```

See [Translations](/docs/ui/translations) for more details.

### Syntax Highlighting

GraphQL pages use Shiki for code blocks. You can customize the highlighter and themes.

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';
import { defaultShikiFactory } from 'fumadocs-core/highlight/shiki/full';

export const GraphQLPage = createGraphQLPage({
  shiki: defaultShikiFactory,
  shikiOptions: {
    themes: {
      light: 'github-light',
      dark: 'github-dark',
    },
  },
});
```

### Custom Components

Override the default heading, code block and Markdown components.

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';

export const GraphQLPage = createGraphQLPage({
  components: {
    Heading({ id, depth, ...props }) {
      const Tag = `h${depth}` as const;
      return <Tag id={id} {...props} />;
    },
    CodeBlock({ lang, code }) {
      return <pre data-lang={lang}>{code}</pre>;
    },
  },
});
```

## Customise UI

For customisations beyond the available options, you can install the UI into your codebase with [Fumadocs CLI](/docs/cli).

### Full UI

The entire UI of GraphQL pages, built on [the headless layer](/docs/integrations/graphql/headless).

```npm
npx @fumadocs/cli add graphql/page
```

It installs `<GraphQLPage />` itself, your `components/api-page.tsx` is no longer needed.

```tsx title="mdx-components.tsx"
import { GraphQLPage } from '@/components/api-page'; // [!code --]
import { GraphQLPage } from '@/components/graphql/page'; // [!code ++]
```

### Parts

Install only the pieces you want to edit, and pass them back.

| Component            | Contents                                      |
| -------------------- | --------------------------------------------- |
| `graphql/operation`  | operations, with their arguments and examples |
| `graphql/type-docs`  | named types, with their fields and usages     |
| `graphql/schema-ui`  | the type, argument and field details          |
| `graphql/playground` | the interactive playground                    |

```tsx title="components/api-page.tsx"
'use client';
import { createGraphQLPage } from '@fumadocs/graphql/ui';
import { Operation } from '@/components/graphql/operation';
import { TypeDocs } from '@/components/graphql/type-docs';

export const GraphQLPage = createGraphQLPage({
  components: {
    Operation,
    TypeDocs,
  },
});
```
