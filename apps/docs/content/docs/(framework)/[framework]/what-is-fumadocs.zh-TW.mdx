**Fumadocs** 框架指的是 UI + Core + 內容來源的組合。與其說 Fumadocs 是一套框架，不如說它更像是一種思維框架，每一層都能各自作為獨立的函式庫使用。

## 設計理念 [#philosophy]

Fumadocs 的誕生，是為了讓建構文件的過程更具自訂彈性，成為一個不強加既定做法的文件框架——**一個您可以打破的「框架」**。

### 更少的抽象層 [#less-abstraction]

雖然大多數框架都透過設定檔進行設定，但當您想微調細節時，它們往往缺乏彈性。
您既無法控制它們如何算繪頁面，也無法掌控其內部邏輯。

Fumadocs 不採用設定檔，而是讓您撰寫程式碼，與軟體的其他部分相互配合；它會讓您清楚了解應用程式的運作方式，並且可完全自訂。

### 無縫整合 [#seamless-integration]

Fumadocs 與您的 React 框架緊密整合，提供實用的工具函式與美觀的 UI。

您依然能使用框架本身的功能，例如**靜態網站生成 (Static Site Generation)&#x20;**。框架的一切仍是您熟悉的樣子。

### 可組合的 UI [#composable-ui]

Fumadocs UI (預設主題) 提供的只有**使用者介面**。這套 UI 有其既定的設計取向，目的是提供更好的行動裝置響應式設計與使用者體驗。

此外，我們採用受 Shadcn UI 啟發、彈性更高的做法。[Fumadocs CLI](/docs/cli) 讓您可以「fork」Fumadocs UI 的部分元件，並完全自訂。

### 伺服器優先 [#server-first-approach]

傳統上，靜態網站產生器都是**靜態**的。

然而，Fumadocs 採用以 React 伺服器元件為基礎的伺服器優先做法。
憑藉明確劃分的伺服器與用戶端邊界，內容得以兼具動態性與互動性。

您可以從伺服器擷取資料來呈現內容，或整合 CMS 以接收即時更新。內容永遠保持最新，維護起來也很輕鬆。

### 精簡 [#minimal]

Fumadocs 由 Fuma 與眾多貢獻者共同維護，並十分重視程式碼庫的可維護性。

我們並不打算滿足所有人想要的每一項功能，而是更專注於把基本功能做到完善，並持續妥善維護。
您也可以透過貢獻，讓 Fumadocs 變得更加實用！

## 何時使用 Fumadocs [#when-to-use-fumadocs]

Fumadocs 在設計上以彈性為核心，不侷限於特定用途。

* `fumadocs-core` 是用於建構文件的無頭式 UI 函式庫。
* `fumadocs-mdx` 是處理 MDX 內容的實用函式庫。

對大多數 Web 應用程式而言，單靠原生 React.js 已經不夠用了。
如今，我們還會想要部落格、作品展示頁、常見問題頁面等。在這些情況下，Fumadocs 能協助您更輕鬆地建構
文件，並減少樣板程式碼。

若您有興趣，可以參閱[比較](/docs/comparisons)。

### 文件 [#documentation]

Fumadocs 專注於**撰寫體驗**，提供美觀的主題以及許多文件自動化工具。

它能協助您更快速地迭代程式碼庫，同時確保文件不會落後。
本網站就是以 Fumadocs 建置的文件網站範例，可供您參考。

### 部落格網站 [#blog-sites]

大多數 React.js 框架本身就足以滿足部落格網站的需求。

Fumadocs 另外提供了語法突顯、文件搜尋及預設主題 (Fumadocs UI) 等工具，
讓您不必重新造輪子。
