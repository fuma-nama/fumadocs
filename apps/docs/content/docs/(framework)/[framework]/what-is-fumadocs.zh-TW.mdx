**Fumadocs** 框架指的是 UI + Core + 內容來源的組合。與其說 Fumadocs 是一套框架，不如說它是一種思維框架，其中每一層都能各自作為獨立的函式庫使用。

## 設計理念 [#philosophy]

Fumadocs 的誕生，是為了讓建構文件的過程更具彈性、更容易自訂，成為一個不預設立場、不強加既定做法的文件框架——**一個您可以打破的「框架」**。

### 更少的抽象 [#less-abstraction]

雖然大多數框架都透過設定檔進行設定，但當您想微調細節時，它們往往不夠有彈性。
您既無法控制它們如何算繪頁面，也無法掌控其內部邏輯。

Fumadocs 希望您親自撰寫程式碼，並與軟體的其他部分相互配合。它不仰賴設定檔，而是讓您清楚了解應用程式的運作方式，並且能完全自訂。

### 無縫整合 [#seamless-integration]

Fumadocs 與您的 React 框架緊密整合，提供實用的工具與美觀的 UI。

您依然可以使用框架原有的功能，例如**靜態網站生成 (Static Site Generation)&#x20;**。框架的一切都和您熟悉的一樣。

### 可組合的 UI [#composable-ui]

Fumadocs UI (預設主題) 唯一提供的就是**使用者介面**。這套 UI 有其明確的設計取向，旨在帶來更好的行動裝置響應式設計與使用者體驗。

此外，我們採用一種受 Shadcn UI 啟發、更具彈性的做法。[Fumadocs CLI](/docs/cli) 可讓您「fork」Fumadocs UI 的部分元件，並完全依需求自訂。

### 伺服器優先的做法 [#server-first-approach]

傳統上，靜態網站產生器都是**靜態的**。

然而，Fumadocs 引入了以 React 伺服器元件 (React Server Component) 為基礎的伺服器優先做法。
透過明確劃分伺服器與用戶端的邊界，內容得以兼具動態性與互動性。

您可以從伺服器擷取資料來呈現內容，也可以與 CMS 整合以接收即時更新。內容永遠保持最新，維護起來也很輕鬆。

### 精簡 [#minimal]

Fumadocs 由 Fuma 與眾多貢獻者共同維護，並特別重視程式碼庫的可維護性。

我們並不打算提供使用者想要的每一項功能，而是更專注於把基本功能做到完善，並持續妥善維護。
您也可以參與貢獻，讓 Fumadocs 變得更加實用！

## 何時使用 Fumadocs [#when-to-use-fumadocs]

Fumadocs 在設計上以彈性為核心，不侷限於特定用途。

* `fumadocs-core` 是用於建構文件的無頭式 UI 函式庫。
* `fumadocs-mdx` 是處理 MDX 內容的實用函式庫。

對大多數 Web 應用程式而言，單靠原生 React.js 已經不夠用了。
如今，我們還會想要部落格、作品展示頁、常見問題頁等。在這些情況下，Fumadocs 能協助您更輕鬆地建構
文件，並減少樣板程式碼。

若您有興趣，可以閱讀[比較](/docs/comparisons)。

### 文件 [#documentation]

Fumadocs 專注於**撰寫體驗**，提供精美的主題以及多種文件自動化工具。

它能協助您更快速地迭代程式碼庫，同時讓文件始終跟上進度。
本網站就是使用 Fumadocs 建置的文件網站範例，可供您參考。

### 部落格網站 [#blog-sites]

大多數 React.js 框架本身就足以應付部落格網站的需求。

Fumadocs 則提供額外的工具，包括語法突顯、文件搜尋，以及預設主題 (Fumadocs UI) ，
讓您不必重新造輪子。
