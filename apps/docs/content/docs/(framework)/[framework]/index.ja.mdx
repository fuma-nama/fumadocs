## 用語 [#terminology]

**Markdown/MDX:** Markdown は、書式付きテキストを作成するためのマークアップ言語です。Fumadocs は Markdown と MDX (Markdown のスーパーセット) をネイティブにサポートしています。

**[Bun](https://bun.sh):** JavaScript ランタイムです。本ガイドではスクリプトの実行に使用します。Node.js を使いたい場合は、代わりに [unrun](https://gugustinette.github.io/unrun/guide/getting-started.html#cli) をお試しください。

より高度なカスタマイズを行うには、React.js の基本的な知識があると役立ちます。

## 自動インストール [#automatic-installation]

Node.js 22以上が必要です。

```npm
npm create fumadocs-app
```

使用する組み込みテンプレートを選択するよう求められます。

* **フレームワーク**: Next.js、React Router、TanStack Start、Waku、Astro
* **コンテンツソース**: Fumadocs MDX、または Astro のコンテンツコレクション

新しい Fumadocs アプリが初期化され、以下の機能がデフォルトで設定されます。

* [LLM 連携](/docs/integrations/llms)
* [動的なメタデータ画像](/docs/integrations/og)

<Callout title="既存のコードベースに導入する場合">
  [手動インストール](/docs/manual-installation)ガイドに従ってセットアップしてください。
</Callout>

### お楽しみください！ [#enjoy]

docs フォルダーに最初の MDX ファイルを作成しましょう。

```mdx title="content/docs/index.mdx"
---
title: Hello World
---

## Yo what's up
```

開発モードでアプリを起動します。

```npm
npm run dev
```

## よくある質問 [#faq]

よく寄せられる質問をまとめています。

<Accordions>
  <Accordion id="upgrade-fumadocs" title="APIが見つからない、バグがあるなどの理由でエラーが発生していますか?">
    お探しのAPIや修正は、新しいバージョンで提供されている可能性があります。[Fumadocsをアップグレード](/docs/upgrade)してから、もう一度お試しください。
  </Accordion>

  <Accordion id="change-base-url" title="ドキュメントのベースルートはどうすれば変更できますか?">
    ルーティングは {frameworkName(props.framework)} が処理します。まず docs ルートを移動してください (`/docs/*` -&gt; `/info/*`) 。

    <show when={props.framework === 'next'}>
      ルートの名前を変更します。

      <Files>
        <Folder name="app/docs" defaultOpen className="opacity-50" disabled>
          <File name="layout.tsx" />
        </Folder>

        <Folder name="app/info" defaultOpen>
          <File name="layout.tsx" />
        </Folder>
      </Files>

      または、ルートグループを使用して `/docs/*` を `/*` に変更することもできます。

      <Files>
        <Folder name="app/(docs)" defaultOpen>
          <File name="layout.tsx" />
        </Folder>
      </Files>
    </show>

    <show when={props.framework === 'react-router'}>
      ```ts title="app/routes.ts"
      import { route, type RouteConfig } from '@react-router/dev/routes';

      export default [
        route('info/*', 'routes/docs.tsx'), // [!code highlight]
        // ...
      ] satisfies RouteConfig;
      ```
    </show>

    <show when={props.framework === 'tanstack-start'}>
      `src/routes/docs/$.tsx` を `src/routes/info/$.tsx` に移動します。
    </show>

    <show when={props.framework === 'waku' || props.framework === 'astro'}>
      `src/pages/docs` を `src/pages/info` に移動します。
    </show>

    最後に、`source.ts` でページのベース URL を更新します。

    ```ts title="lib/source.ts"
    import { loader } from 'fumadocs-core/source';

    export const source = loader({
      baseUrl: '/info', // 新しい値に変更 [!code highlight]
    });
    ```

    テンプレートでは、この値は `lib/shared.ts` 内で `docsRoute` として定義されています。Markdown のリンクにも反映されるよう、変更する際はこの値を編集してください。
  </Accordion>

  <Accordion id="multi-docs" title="複数のドキュメントを実装するにはどうすればよいですか?">
    [レイアウトタブ](/docs/ui/layouts/docs#layout-tabs)の使用をおすすめします。
  </Accordion>

  <show when={props.framework === 'next' || props.framework === 'astro'}>
    <Accordion id="custom-layout-docs-page" title="Docs レイアウトを使わずに /docs 配下にページを作成するには?">
      <show when={props.framework === 'next'}>
        Next.js App Router でのレイアウト管理と同様に、コンテンツディレクトリ(`/content/docs`)から元の MDX ファイルを削除します。
        これにより、ページの重複によるエラーを防げます。

        次に、Docs レイアウトの配下にない別のルートグループにページを追加します。

        例えば、`/docs/test` を置き換える場合は次のようになります。

        <Files>
          <File name="(home)/docs/test/page.tsx" />

          <Folder name="docs" defaultOpen>
            <File name="layout.tsx" />

            <File name="[[...slug]]/page.tsx" />
          </Folder>
        </Files>

        `/docs` の場合は、catch-all ルートを optional ではない形式に変更する必要があります。

        <Files>
          <File name="(home)/docs/page.tsx" />

          <Folder name="docs" defaultOpen>
            <File name="layout.tsx" />

            <File name="[...slug]/page.tsx" />
          </Folder>
        </Files>
      </show>

      <show when={props.framework === 'astro'}>
        `Docs` アイランドを使用しない独立した `.astro` ページを `src/pages/docs/` に作成します。同じ URL が重複しないよう、`content/docs` から対応する MDX ファイルを削除してください。
      </show>
    </Accordion>
  </show>

  <show when={props.framework === 'react-router' || props.framework === 'tanstack-start' || props.framework === 'waku'}>
    <Accordion id="vite-context-error" title="React コンテキストでエラーが発生する場合">
      Vite の事前バンドルには、不可解な問題がいくつかあります ([#3910](https://github.com/vitejs/vite/issues/3910)) 。
      Fumadocs を事前バンドルの対象から除外し、`noExternal` に追加してください。

      ```ts title="vite.config.ts"
      import { defineConfig } from 'vite';

      export default defineConfig({
        resolve: {
          // 必要に応じて、Fumadocs の他の依存パッケージも追加してください
          noExternal: ['fumadocs-core', 'fumadocs-ui', 'fumadocs-openapi', '@fumadocs/base-ui'],
        },
      });
      ```
    </Accordion>
  </show>

  <show when={props.framework === 'next'}>
    <Accordion id="node-issues" title="Node.js の既知の問題">
      次のような Turbopack のエラーが発生する場合:

      ```
      JSON file not found: FileSystemPath { ... path: "lib/locales/sources/file.json.json" }
      ```

      通常、`require(esm)` がサポートされていないことが原因です([#3312](https://github.com/fuma-nama/fumadocs/issues/3312))。Node.js 22 以上にアップグレードしてください。

      Node.js 23.1 で、本番ビルド時に次のエラーが発生した場合:

      ```
      Could not find a production build in the '.next' directory.
      ```

      これは既知の問題です([#1021](https://github.com/fuma-nama/fumadocs/issues/1021) を参照)。Node.js を 23.6.0 以上にアップグレードしてください。
    </Accordion>

    <Accordion id="dynamic-route" title="動的ルートを使用していますが、パフォーマンスに問題はありませんか?">
      Next.js では、`generateStaticParams` を設定すると動的ルートが静的ルートに変換されます。
      そのため、静的ページと同等の速度で表示されます。

      [静的エクスポートを有効にする](/docs/deploying/static)と、静的なビルド出力を得ることもできます。
    </Accordion>
  </show>
</Accordions>
