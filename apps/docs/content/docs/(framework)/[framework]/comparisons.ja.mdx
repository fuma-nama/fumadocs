## Nextra [#nextra]

Fumadocs は Nextra から大きな影響を受けており、ルーティング規約などはその一例です。そのため、
Fumadocs にも `meta.json` が存在します。

Nextra は Fumadocs よりも設計方針が明確に定められています。その反面、
設定ファイルを編集するだけで済む Nextra とは異なり、Fumadocs では手動で設定を行う必要があります。

既存のコードベースへの導入や高度なルーティングの実装など、あらゆる部分を
より細かく制御したい場合には、Fumadocs が最適です。

## Mintlify [#mintlify]

Mintlify はドキュメントサービスです。Fumadocs とは異なり、無料プランはあるものの、完全に無料でもオープンソースでもありません。

Fumadocs は Mintlify ほど高機能ではありません。たとえば、Mintlify の OpenAPI 連携がその一例です。
Fumadocs の作者としては、現在のドキュメント作成方法に満足しているのであれば、Mintlify から Fumadocs への乗り換えはおすすめしません。
とはいえ、Fumadocs は洗練されたドキュメントを作りたいすべての React.js 開発者に適したツールだと考えています。

## Docusaurus [#docusaurus]

Docusaurus は React.js をベースにした強力なフレームワークです。
プラグインやカスタムテーマを通じて、多くの便利な機能を利用できます。

### 複雑さが低い [#lower-complexity]

Fumadocs は React フレームワークとの統合を前提に設計されているため、使い始めるには React.js についてある程度深い知識が必要になる場合があります。
その代わり、Fumadocs はカスタマイズ性に優れています。

シンプルなドキュメントで、フレームワーク固有の機能が不要な場合は、Docusaurus のほうが適しているかもしれません。

### プラグイン [#plugins]

プラグインを使えば、多くのことを簡単に実現できます。実際、Docusaurus のエコシステムはより大規模で、多くのコントリビューターによってメンテナンスされています。

一方、Fumadocs は柔軟性が高いため同様の機能を自分で実装できますが、納得のいく形に仕上げるまでには時間がかかる場合があります。
