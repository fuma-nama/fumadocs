## Docs for LLM

Serve your docs as Markdown for LLMs and AI agents:

```package-install
npx @fumadocs/cli feature llms
```

It enables processed Markdown on your docs collection, adds `docsLlms` to `lib/source.ts`, and serves the [files](#files) below. The generated files are listed here if you prefer a manual setup.

### `docsLlms`

`llms()` renders your docs for LLMs. `renderPage` turns one page into Markdown, from the processed document rather than the raw file content:

<feature title="lib/source.ts">llms/docs-llms.ts</feature>

| Method         | Output                                         |
| -------------- | ---------------------------------------------- |
| `index(lang?)` | the `llms.txt` index, built from the page tree |
| `page(page)`   | one page, rendered with `renderPage`           |
| `full(lang?)`  | every page rendered with `renderPage`, joined  |
| `files()`      | the paths of the [files for agents](#files)    |
| `serve(path)`  | the response for the file at a path            |

<Callout title="renderPage is required">
  `page()`, `full()`, `files()` and `serve()` are only available when you pass `renderPage`, since
  Fumadocs cannot know how your content source exposes its Markdown.
</Callout>

`renderPage` reads the processed Markdown of pages, so enable `includeProcessedMarkdown`:

<show when={props.framework !== 'astro'}>

<feature title="source.config.ts">llms/source.config.ts</feature>

MDX components appear as JSX syntax. To render them into their [Markdown form](/docs/headless/utils/markdown#asmarkdown), [pass your MDX components](/docs/headless/mdx/remark-llms#jsx-elements) as page props.

</show>

<show when={props.framework === 'astro'}>

```js title="astro.config.mjs"
import { defineConfig } from 'astro/config';
import fumadocs from '@fumadocs/astro';

export default defineConfig({
  integrations: [
    fumadocs({
      includeProcessedMarkdown: true, // [!code ++]
    }),
  ],
});
```

MDX components appear as JSX syntax unless they define their [Markdown form](/docs/headless/utils/markdown#asmarkdown).

</show>

Runtime content sources like [`@fumadocs/local-md`](/docs/integrations/content/local-md) resolve on demand. Pass their `getSource` and the CLI generates the same files:

```ts
export const docsLlms = llms(getSource, {
  renderPage: (page) => `# ${page.data.title} (${page.url})

${page.data.content}`,
});
```

With `getSource`, `index()` and `indexNode()` return a promise instead of a string.

### Files

The CLI serves these files for AI agents:

- `/llms.txt`: an index of every page, linked to its Markdown, followed by the `llms-full.txt` of each section.
- `/llms-full.txt`: the content of every page.
- `<dir>/llms-full.txt`: the pages under a URL directory with two or more pages, like `/docs/ui/llms-full.txt`, so agents can read large docs one section at a time.
- `<page>.md`: the Markdown of a page, like `/docs/ui.md`, and `/index.md` for `/`.

To leave pages out of the files, like drafts, pass `filter`. `llms.txt` still lists them, linked to their HTML page:

```ts title="lib/source.ts"
export const docsLlms = llms(source, {
  filter: (page) => page.slugs[0] !== 'drafts',
  renderPage: async (page) => `# ${page.data.title}\n\n${await page.data.getText('processed')}`,
});
```

In the files, `renderUrl` receives the path of the file that a link points to, like the `.md` file of a page.

Agents that read the HTML of a page find its Markdown through a link in the `<head>`:

```html
<link rel="alternate" type="text/markdown" href="/docs/ui.md" />
```

#### Static Output [#static-output]

With `output: 'export'`, Next.js has no rewrites. The `/llms.mdx/[...path]` route serves the files at their prefixed paths, like `/llms.mdx/docs/ui.md`, and `renderUrl` points the links of `llms.txt` there:

<show when={props.framework === 'react-router'}>

In SPA mode, prerender the files in `react-router.config.ts`. React Router loads the config without your Vite plugins, so load the source with `runnerImport` of Vite:

```ts title="react-router.config.ts"
import type { Config } from '@react-router/dev/config';
import { fumadocsMdx } from 'fumadocs-mdx/vite';
import { runnerImport } from 'vite';

export default {
  ssr: false,
  async prerender({ getStaticPaths }) {
    const paths = getStaticPaths();
    const { docsLlms } = (
      await runnerImport<typeof import('./app/lib/source')>('./app/lib/source.ts', {
        plugins: [fumadocsMdx()],
        resolve: { tsconfigPaths: true },
      })
    ).module;

    for (const path of await docsLlms.files())
      paths.push(path === '/llms.txt' || path === '/llms-full.txt' ? path : `/llms.mdx${path}`);
    return paths;
  },
} satisfies Config;
```

</show>

<show when={props.framework === 'tanstack-start'}>

In SPA mode, prerender the files with Nitro. TanStack Start requests prerendered paths with a trailing slash, which the routes of files don't match. Vite loads the config without your plugins, so load the source with `runnerImport`:

```ts title="vite.config.ts"
import { defineConfig, runnerImport } from 'vite';
import { fumadocsMdx } from 'fumadocs-mdx/vite';
import { nitro } from 'nitro/vite';

const { docsLlms } = (
  await runnerImport<typeof import('./src/lib/source')>('./src/lib/source.ts', {
    plugins: [fumadocsMdx()],
    resolve: { tsconfigPaths: true },
  })
).module;

export default defineConfig({
  plugins: [
    // other plugins
    nitro({
      prerender: { routes: await docsLlms.files() },
    }),
  ],
});
```

</show>

#### `Accept`

<show when={props.framework !== 'astro'}>

AI agents can ask for Markdown with the `Accept` header.

</show>

<show when={props.framework === 'next'}>

Serve the Markdown of a page when the request prefers it:

```ts title="proxy.ts"
import { NextRequest, NextResponse } from 'next/server';
import { isMarkdownPreferred, rewritePath } from 'fumadocs-core/negotiation';

const { rewrite: rewriteDocs } = rewritePath('/docs{/*path}', '/llms.mdx/docs{/*path}.md');

export default function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl;
  // the rewrites of the Next.js config serve files like `/docs/ui.md`
  const result =
    isMarkdownPreferred(request) && !/\.(md|txt)$/.test(pathname) && rewriteDocs(pathname);

  if (result) {
    return NextResponse.rewrite(new URL(result, request.nextUrl), {
      headers: { Vary: 'Accept' }, // [!code highlight]
    });
  }

  return NextResponse.next();
}
```

</show>

<show when={props.framework === 'react-router' || props.framework === 'waku'}>

The middleware above responds with the Markdown of a docs page when the request prefers it.

<Callout>
  Prerendered pages are served as static files before the middleware runs, so they always respond
  with HTML.
</Callout>

</show>

<show when={props.framework === 'tanstack-start'}>

Redirect to the Markdown of a page when the request prefers it:

```ts title="src/start.ts"
import { createMiddleware, createStart } from '@tanstack/react-start';
import { redirect } from '@tanstack/react-router';
import { isMarkdownPreferred } from 'fumadocs-core/negotiation';

const llmMiddleware = createMiddleware().server(({ next, request }) => {
  const url = new URL(request.url);

  // the routes of files serve paths like `/docs/ui.md`
  if (
    url.pathname.startsWith('/docs') &&
    !/\.(md|txt)$/.test(url.pathname) &&
    isMarkdownPreferred(request)
  ) {
    url.pathname += '.md';
    throw redirect({ href: url.href, headers: { Vary: 'Accept' } }); // [!code highlight]
  }

  return next();
});

export const startInstance = createStart(() => ({
  requestMiddleware: [llmMiddleware],
}));
```

</show>

<show when={props.framework !== 'astro'}>

The same URL now has two representations, so the response needs `Vary: Accept` to prevent cache collisions.

</show>

<show when={props.framework === 'next'}>

<Callout>
  Next.js discards `Vary` on App Router page responses, so the HTML responses of docs pages can't
  carry the header. Set it at your CDN if a shared cache serves your docs.
</Callout>

</show>

<show when={props.framework === 'astro'}>

Docs pages can't serve Markdown based on the `Accept` header. Astro middleware only runs for pages rendered on request, while docs pages are prerendered.

</show>

### Page Actions

Page actions let readers copy the Markdown of a page, or open the page in AI apps. They read the [`.md` file](#files) of the page.

![AI Page Actions](/docs/ai-page-actions.png)

<show when={props.framework === 'next' || props.framework === 'waku'}>

Render them in your docs page:

```tsx
import { MarkdownCopyButton, ViewOptionsPopover } from 'fumadocs-ui/layouts/docs/page';

const markdownUrl = `${page.url}.md`;

<div className="flex flex-row gap-2 items-center border-b pt-2 pb-6">
  <MarkdownCopyButton markdownUrl={markdownUrl} />
  <ViewOptionsPopover
    markdownUrl={markdownUrl}
    githubUrl={`https://github.com/${owner}/${repo}/blob/main/content/docs/${encodeURI(page.path)}`}
  />

```

</show>

<show when={props.framework === 'next'}>

## MCP Server

Expose your docs to AI agents through a [MCP](https://modelcontextprotocol.io) server, with tools to list, search and read pages.

```package-install
npx @fumadocs/cli feature mcp
```

It creates a `/api/mcp` route with the streamable HTTP transport, on top of the [LLM routes](#docs-for-llm) above.

The tools come from [`fumadocs-core/mcp`](/docs/headless/utils/mcp).

Connect an agent to it with:

```json
{
  "mcpServers": {
    "docs": { "url": "https://your-site.com/api/mcp" }
  }
}
```

## WebMCP

<Callout type="warn" title="Experimental">
  [WebMCP](https://webmachinelearning.github.io/webmcp/) is an early web standard, available in
  Chrome 149+ behind the `#enable-webmcp-testing` flag and an origin trial. The API may still
  change.
</Callout>

Where the MCP server above serves agents connecting to your site, WebMCP exposes tools to the AI agent
of the browser, on the page the reader is viewing.

```package-install
npx @fumadocs/cli feature webmcp
```

It creates a `WebMCP` component on top of the [LLM routes](#docs-for-llm). Render it inside `<RootProvider />`.

- `search_docs` queries the search API route. You can replace `fetchClient` with [other clients](/docs/search).
- `read_page` fetches the Markdown of a page, from <show when={props.framework === 'react-router'}>`/llms.mdx/docs/page.md`</show><show when={props.framework !== 'react-router'}>`/docs/page.md`</show>.

## Ask AI

![AI Search](/docs/ai-search.png)

You can install the AI chat dialog using Fumadocs CLI.

<Tabs items={['AI SDK', 'LLMGateway', 'Inkeep AI']}>
<Tab>

```npm
npx @fumadocs/cli add ai/openrouter
```

It's automatically configured for [OpenRouter](https://openrouter.ai) using Vercel AI SDK, with a `/search` tool for AI.

You can use other models by updating the `/api/chat` route.

> Fumadocs doesn't provide the AI model, it's up to you.
>
> Your AI model can use the `llms-full.txt` file generated above, or more diversified sources of information when combined with 3rd party solutions.

</Tab>
<Tab>

```npm
npx @fumadocs/cli add ai/llmgateway
```

It's automatically configured for [LLMGateway](https://llmgateway.io) using Vercel AI SDK, with a `/search` tool for AI.

LLMGateway is an open-source API gateway that proxies requests to 300+ language models, so the same route handler can switch between providers by changing the model ID.

Add your LLMGateway API key to environment variables:

```dotenv
LLM_GATEWAY_API_KEY="..."
```

By default the route uses `anthropic/claude-3.5-sonnet`. To switch to any other model supported by LLMGateway, set the `LLM_GATEWAY_MODEL` environment variable. No code change is required:

```dotenv
# any model id from https://llmgateway.io/models
LLM_GATEWAY_MODEL="openai/gpt-4o"
```

</Tab>
<Tab>

```npm
npx @fumadocs/cli add ai/inkeep
```

It's automatically configured for [Inkeep AI](https://inkeep.com) using Vercel AI SDK.

Add your Inkeep API key to environment variables:

```dotenv
INKEEP_API_KEY="..."
```

</Tab>

Docs layouts render the chat from their `aiChat` option. The option takes client state, so create a client component for your layout and use it in place of the original layout:

```tsx tab="components/ai/layout.tsx"
'use client';
// or the Notebook, Glass and Spacious layouts
import { DocsLayout as Layout, type DocsLayoutProps } from 'fumadocs-ui/layouts/docs';
// the installed components
import { AIChat, AIChatPanel, useAIChat } from './search';

export function DocsLayout(props: DocsLayoutProps) {
  return (
    <AIChat>
      <ChatLayout {...props} />
    </AIChat>
  );
}

function ChatLayout(props: DocsLayoutProps) {
  const { open, setOpen } = useAIChat();

  return (
    <Layout
      {...props}
      aiChat={{ open, onOpenChange: setOpen, panel: <AIChatPanel />, trigger: true }}
    />
  );
}
```
