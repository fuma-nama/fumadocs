## 供 LLM 使用的文件 [#docs-for-llm]

以 Markdown 格式提供您的文件，供 LLM 與 AI 代理使用：

```package-install
npx @fumadocs/cli feature llms
```

它會為您的 docs 集合啟用處理後的 Markdown，在 `lib/source.ts` 中加入 `docsLlms`，並提供下方的[檔案](#files)。若您偏好手動設定，可參考以下列出的產生檔案。

### `docsLlms` [#docsllms]

`llms()` 會為 LLM 算繪您的文件。`renderPage` 會將單一頁面轉換為 Markdown，依據的是處理後的文件，而非原始檔案內容：

<feature title="lib/source.ts">llms/docs-llms.ts</feature>

| 方法             | 輸出                        |
| -------------- | ------------------------- |
| `index(lang?)` | `llms.txt` 索引，依頁面樹建立      |
| `page(page)`   | 單一頁面，以 `renderPage` 算繪    |
| `full(lang?)`  | 以 `renderPage` 算繪後合併的所有頁面 |
| `files()`      | [供 AI 代理使用的檔案](#files)的路徑 |
| `serve(path)`  | 指定路徑上檔案的回應                |

<Callout title="renderPage 為必要項目">
  只有在傳入 `renderPage` 時，才能使用 `page()`、`full()`、`files()` 與 `serve()`，因為
  Fumadocs 無從得知您的內容來源如何提供 Markdown。
</Callout>

`renderPage` 會讀取頁面處理後的 Markdown，因此請啟用 `includeProcessedMarkdown`：

<show when={props.framework !== 'astro'}>
  <feature title="source.config.ts">llms/source.config.ts</feature>

  MDX 元件會以 JSX 語法呈現。若要將其算繪為 [Markdown 形式](/docs/headless/utils/markdown#asmarkdown)，請將[您的 MDX 元件](/docs/headless/mdx/remark-llms#jsx-elements)作為頁面 props 傳入。
</show>

<show when={props.framework === 'astro'}>
  ```js title="astro.config.mjs"
  import { defineConfig } from 'astro/config';
  import fumadocs from '@fumadocs/astro';

  export default defineConfig({
    integrations: [
      fumadocs({
        includeProcessedMarkdown: true, // [!code ++]
      }),
    ],
  });
  ```

  除非 MDX 元件定義了自身的 [Markdown 形式](/docs/headless/utils/markdown#asmarkdown)，否則會以 JSX 語法呈現。
</show>

[`@fumadocs/local-md`](/docs/integrations/content/local-md) 等執行階段內容來源會隨需解析。只要傳入其 `getSource`，CLI 就會產生相同的檔案：

```ts
export const docsLlms = llms(getSource, {
  renderPage: (page) => `# ${page.data.title} (${page.url})

${page.data.content}`,
});
```

使用 `getSource` 時，`index()` 與 `indexNode()` 會回傳 Promise，而不是字串。

### 檔案 [#files]

CLI 會為 AI 代理提供以下檔案：

* `/llms.txt`：文件的索引，附有每個頁面 Markdown 版本的連結。
* `/llms-full.txt`：所有頁面的內容。
* `<page>.md`：單一頁面的 Markdown，例如 `/docs/ui.md`。位於 `/` 的頁面則對應 `/index.md`。
* `<section>/llms-full.txt`：某個[區段](#sections)的內容，例如 `/docs/ui/llms-full.txt`。

若要將特定頁面 (例如草稿) 排除在這些檔案之外，請傳入 `filter`。`llms.txt` 仍會列出這些頁面，但改為連結至其 HTML 頁面：

```ts title="lib/source.ts"
export const docsLlms = llms(source, {
  filter: (page) => page.slugs[0] !== 'drafts',
  renderPage: async (page) => `# ${page.data.title}\n\n${await page.data.getText('processed')}`,
});
```

在這些檔案中，`renderUrl` 會接收連結所指向檔案的路徑，例如頁面的 `.md` 檔案。

讀取頁面 HTML 的 AI 代理會透過 `<head>` 中的連結找到該頁面的 Markdown：

```html
<link rel="alternate" type="text/markdown" href="/docs/ui.md" />
```

### 區段 [#sections]

區段是頁面樹中擁有專屬 `llms-full.txt` 的資料夾，讓 AI 代理能逐段閱讀大型文件。預設情況下，每個根資料夾都是一個區段。在 `llms.txt` 中，該資料夾對應的那一行會連結到其所屬區段的 `llms-full.txt`。

若要自訂哪些資料夾作為區段，請傳入 `section`。它會接收一個資料夾，並回傳該資料夾是否為區段：

```ts title="lib/source.ts"
export const docsLlms = llms(source, {
  // 所有含 index 頁面的資料夾
  section: (folder) => folder.index !== undefined,
  renderPage: async (page) => `# ${page.data.title}\n\n${await page.data.getText('processed')}`,
});
```

在大型網站上，您可以收合區段，讓 `llms.txt` 保持簡短。收合的區段在 `llms.txt` 中只會列為一個連結，指向該區段專屬的 `<section>/llms.txt`，再由該檔案列出區段內的頁面：

```ts title="lib/source.ts"
export const docsLlms = llms(source, {
  section: (folder) => (folder.root ? { collapse: true } : false),
  renderPage: async (page) => `# ${page.data.title}\n\n${await page.data.getText('processed')}`,
});
```

區段的檔案會透過其資料夾索引頁面的 URL 提供。若資料夾沒有索引頁面，則改用其頁面所在的 URL 目錄。當兩個資料夾共用同一個 URL 時 (例如資料夾群組) ，請傳入 `asPath`，讓其中一個改由另一個路徑提供，例如 `{ asPath: '/docs/guides' }`。

  <feature title="lib/source.ts">llms/docs-llms-prefixed.ts</feature>

<show when={props.framework === 'react-router'}>
  在 SPA 模式下，請在 `react-router.config.ts` 中預先算繪這些檔案。React Router 載入設定時不會套用您的 Vite 外掛，因此請使用 Vite 的 `runnerImport` 載入來源：

  ```ts title="react-router.config.ts"
  import type { Config } from '@react-router/dev/config';
  import { fumadocsMdx } from 'fumadocs-mdx/vite';
  import { runnerImport } from 'vite';

  export default {
    ssr: false,
    async prerender({ getStaticPaths }) {
      const paths = getStaticPaths();
      const { docsLlms } = (
        await runnerImport<typeof import('./app/lib/source')>('./app/lib/source.ts', {
          plugins: [fumadocsMdx()],
          resolve: { tsconfigPaths: true },
        })
      ).module;

      for (const path of await docsLlms.files())
        paths.push(path === '/llms.txt' || path === '/llms-full.txt' ? path : `/llms.mdx${path}`);
      return paths;
    },
  } satisfies Config;
  ```
</show>

<show when={props.framework === 'tanstack-start'}>
  在 SPA 模式下，請使用 Nitro 預先算繪這些檔案。TanStack Start 請求預先算繪的路徑時會加上結尾斜線，導致檔案的路由無法比對。Vite 載入設定時不會套用您的外掛，因此請使用 `runnerImport` 載入來源：

  ```ts title="vite.config.ts"
  import { defineConfig, runnerImport } from 'vite';
  import { fumadocsMdx } from 'fumadocs-mdx/vite';
  import { nitro } from 'nitro/vite';

      plugins: [fumadocsMdx()],
      resolve: { tsconfigPaths: true },
    })
  ).module;

  export default defineConfig({
    plugins: [
      // 其他外掛
      nitro({
        prerender: { routes: await docsLlms.files() },
      }),
    ],
  });
  ```
</show>

<show when={props.framework === 'waku'}>
  API 路由會預先算繪，因此以靜態檔案部署的 Waku 網站仍會在 `/llms.mdx` 下提供這些檔案。中介軟體則需要伺服器才能運作。

#### `Accept` [#accept]

<show when={props.framework !== 'astro'}>
  AI 代理可以透過 `Accept` 標頭要求取得 Markdown。
</show>

<show when={props.framework === 'next'}>
  當請求偏好 Markdown 時，改為提供該頁面的 Markdown：

  ```ts title="proxy.ts"
  import { NextRequest, NextResponse } from 'next/server';
  import { isMarkdownPreferred, rewritePath } from 'fumadocs-core/negotiation';

  const { rewrite: rewriteDocs } = rewritePath('/docs{/*path}', '/llms.mdx/docs{/*path}.md');

  export default function proxy(request: NextRequest) {
    const { pathname } = request.nextUrl;
    // Next.js 設定中的 rewrites 會提供 `/docs/ui.md` 這類檔案
    const result =
      isMarkdownPreferred(request) && !/\.(md|txt)$/.test(pathname) && rewriteDocs(pathname);

    if (result) {
      return NextResponse.rewrite(new URL(result, request.nextUrl), {
        headers: { Vary: 'Accept' }, // [!code highlight]
      });
    }

    return NextResponse.next();
  }
  ```
</show>

<show when={props.framework === 'react-router' || props.framework === 'waku'}>
  當請求偏好 Markdown 時，上述中介軟體會以文件頁面的 Markdown 回應。

  <Callout>
    預先算繪的頁面會在中介軟體執行前就以靜態檔案提供，因此一律回應 HTML。
  </Callout>
</show>

<show when={props.framework === 'tanstack-start'}>
  當請求偏好 Markdown 時，重新導向至該頁面的 Markdown：

  ```ts title="src/start.ts"
  import { createMiddleware, createStart } from '@tanstack/react-start';
  import { redirect } from '@tanstack/react-router';
  import { isMarkdownPreferred } from 'fumadocs-core/negotiation';

  const llmMiddleware = createMiddleware().server(({ next, request }) => {
    const url = new URL(request.url);

    // 檔案路由會提供 `/docs/ui.md` 這類路徑
    if (
      url.pathname.startsWith('/docs') &&
      !/\.(md|txt)$/.test(url.pathname) &&
      isMarkdownPreferred(request)
    ) {
      url.pathname += '.md';
      throw redirect({ href: url.href, headers: { Vary: 'Accept' } }); // [!code highlight]
    }

    return next();
  });

  export const startInstance = createStart(() => ({
    requestMiddleware: [llmMiddleware],
  }));
  ```
</show>

<show when={props.framework !== 'astro'}>
  同一個 URL 現在有兩種呈現形式，因此回應需要加上 `Vary: Accept`，以避免快取衝突。
</show>

<show when={props.framework === 'next'}>
  <Callout>
    Next.js 會捨棄 App Router 頁面回應中的 `Vary`，因此文件頁面的 HTML 回應無法帶有此標頭。若您的文件經由共用快取提供，請在 CDN 上設定此標頭。
  </Callout>
</show>

<show when={props.framework === 'astro'}>
  文件頁面無法依據 `Accept` 標頭提供 Markdown。Astro 中介軟體只會在請求時才算繪的頁面上執行，而文件頁面是預先算繪的。
</show>

## MCP 伺服器 [#mcp-server]

透過 [MCP](https://modelcontextprotocol.io) 伺服器將您的文件開放給 AI 代理使用，並提供可列出、搜尋及讀取頁面的工具。

```package-install
npx @fumadocs/cli feature mcp
```

它會在上述 [LLM 路由](#docs-for-llm)的基礎上，建立一個使用 streamable HTTP 傳輸層的 `/api/mcp` 路由。

這些工具來自 [`fumadocs-core/mcp`](/docs/headless/utils/mcp)。

您可以透過以下方式將 AI 代理連接至此路由：

```json
{
  "mcpServers": {
    "docs": { "url": "https://your-site.com/api/mcp" }
  }
}
```

## WebMCP [#webmcp]

<Callout type="warn" title="實驗性功能">
  [WebMCP](https://webmachinelearning.github.io/webmcp/) 是一項仍處於早期階段的網頁標準，目前可在
  Chrome 149+ 中透過 `#enable-webmcp-testing` 旗標及來源試用 (origin trial) 使用。其 API 仍可能
  變動。
</Callout>

上述 MCP 伺服器服務的是連線至您網站的 AI 代理，而 WebMCP 則是在讀者目前瀏覽的頁面上，將工具提供給瀏覽器的 AI 代理。

```package-install
npx @fumadocs/cli feature webmcp
```

這會以 [LLM 路由](#docs-for-llm)為基礎建立一個 `WebMCP` 元件。請將它算繪在 `<RootProvider />` 內。

* `search_docs` 會查詢搜尋 API 路由。您可以將 `fetchClient` 替換為[其他用戶端](/docs/search)。
* `read_page` 會從 <show when={props.framework === 'react-router' || props.framework === 'waku'}>`/llms.mdx/docs/page.md`</show><show when={props.framework !== 'react-router' && props.framework !== 'waku'}>`/docs/page.md`</show> 擷取頁面的 Markdown 內容。
