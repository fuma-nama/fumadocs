## LLM向けのドキュメント [#docs-for-llm]

ドキュメントをMarkdown形式でLLMやAIエージェントに提供できます。

```package-install
npx @fumadocs/cli feature llms
```

これにより、docs コレクションで処理済みの Markdown が有効になり、`lib/source.ts` に `docsLlms` が追加され、以下の[ファイル](#files)が配信されます。手動でセットアップする場合に備えて、生成されるファイルを以下に示します。

### `docsLlms` [#docsllms]

`llms()` は、ドキュメントを LLM 向けにレンダリングします。`renderPage` は、生のファイル内容ではなく処理済みのドキュメントをもとに、1 つのページを Markdown に変換します。

<feature title="lib/source.ts">llms/docs-llms.ts</feature>

| メソッド           | 出力                                |
| -------------- | --------------------------------- |
| `index(lang?)` | ページツリーから構築される `llms.txt` インデックス   |
| `page(page)`   | `renderPage` でレンダリングした単一ページ       |
| `full(lang?)`  | `renderPage` でレンダリングした全ページを結合したもの |
| `files()`      | [エージェント向けファイル](#files)のパス         |
| `serve(path)`  | 指定したパスにあるファイルのレスポンス               |

<Callout title="renderPage は必須です">
  `page()`、`full()`、`files()`、`serve()` は、`renderPage` を渡した場合にのみ利用できます。
  コンテンツソースが Markdown をどのように公開しているかを、Fumadocs 側では把握できないためです。
</Callout>

`renderPage` はページの処理済み Markdown を読み込むため、`includeProcessedMarkdown` を有効にしてください。

<show when={props.framework !== 'astro'}>
  <feature title="source.config.ts">llms/source.config.ts</feature>

  MDX コンポーネントは JSX 構文のまま出力されます。これらを [Markdown 形式](/docs/headless/utils/markdown#asmarkdown)にレンダリングするには、[MDX コンポーネントを](/docs/headless/mdx/remark-llms#jsx-elements)ページの props として渡してください。
</show>

<show when={props.framework === 'astro'}>
  ```js title="astro.config.mjs"
  import { defineConfig } from 'astro/config';
  import fumadocs from '@fumadocs/astro';

  export default defineConfig({
    integrations: [
      fumadocs({
        includeProcessedMarkdown: true, // [!code ++]
      }),
    ],
  });
  ```

  MDX コンポーネントは、[Markdown 形式](/docs/headless/utils/markdown#asmarkdown)を定義していない限り、JSX 構文のまま出力されます。
</show>

[`@fumadocs/local-md`](/docs/integrations/content/local-md) のようなランタイムのコンテンツソースは、リクエスト時にオンデマンドで解決されます。その `getSource` を渡せば、CLI が同じファイルを生成します。

```ts
export const docsLlms = llms(getSource, {
  renderPage: (page) => `# ${page.data.title} (${page.url})

${page.data.content}`,
});
```

`getSource` を使用する場合、`index()` と `indexNode()` は文字列ではなく Promise を返します。

### ファイル [#files]

CLIは、AIエージェント向けに次のファイルを配信します。

* `/llms.txt`: ドキュメントのインデックスです。各ページのMarkdownへのリンクが含まれます。
* `/llms-full.txt`: すべてのページのコンテンツです。
* `<page>.md`: ページのMarkdownです(例: `/docs/ui.md`)。`/` のページは `/index.md` になります。
* `<section>/llms-full.txt`: [セクション](#sections)のコンテンツです(例: `/docs/ui/llms-full.txt`)。

下書きなど、特定のページをこれらのファイルから除外するには `filter` を渡します。除外したページも `llms.txt` には引き続き掲載され、HTMLページへのリンクになります。

```ts title="lib/source.ts"
export const docsLlms = llms(source, {
  filter: (page) => page.slugs[0] !== 'drafts',
  renderPage: async (page) => `# ${page.data.title}\n\n${await page.data.getText('processed')}`,
});
```

これらのファイルでは、`renderUrl` はリンク先のファイルのパス(ページの `.md` ファイルなど)を受け取ります。

ページの HTML を読み取るエージェントは、次のように `<head>` 内のリンクからそのページの Markdown を見つけます。

```html
<link rel="alternate" type="text/markdown" href="/docs/ui.md" />
```

### セクション [#sections]

セクションとは、独自の `llms-full.txt` を持つページツリー内のフォルダーです。これにより、エージェントは大規模なドキュメントを部分ごとに読み込めます。デフォルトでは、すべてのルートフォルダーがセクションになります。`llms.txt` では、各フォルダーの行がそのセクションの `llms-full.txt` へのリンクになります。

どのフォルダーをセクションにするかを指定するには、`section` を渡します。この関数はフォルダーを受け取り、そのフォルダーがセクションかどうかを返します。

```ts title="lib/source.ts"
export const docsLlms = llms(source, {
  // index ページを持つすべてのフォルダー
  section: (folder) => folder.index !== undefined,
  renderPage: async (page) => `# ${page.data.title}\n\n${await page.data.getText('processed')}`,
});
```

大規模なサイトでは、セクションを折りたたむことで `llms.txt` を短く保てます。折りたたんだセクションは、`llms.txt` ではそのセクション専用の `<section>/llms.txt` への1つのリンクとして掲載され、セクション内のページはそのファイルに一覧表示されます。

```ts title="lib/source.ts"
export const docsLlms = llms(source, {
  section: (folder) => (folder.root ? { collapse: true } : false),
  renderPage: async (page) => `# ${page.data.title}\n\n${await page.data.getText('processed')}`,
});
```

セクションのファイルは、そのフォルダーのインデックスページの URL で配信されます。インデックスページがないフォルダーでは、代わりに配下のページの URL ディレクトリが使用されます。フォルダーグループのように 2 つのフォルダーが同じ URL を共有する場合は、`{ asPath: '/docs/guides' }` のように `asPath` を渡して、一方を別のパスで配信してください。

### ルート [#routes]

`files()` はファイルのパスを一覧で返し、`serve(path)` は指定したパスのファイルをレスポンスとして返します。そのため、各ルートではリクエストパスを `serve()` に渡すだけで済みます。

  `/llms.txt` と `/llms-full.txt` はルートハンドラーで配信します。その他のファイルは `app/docs/[[...slug]]` と同じ階層に置かれるため、Next.js の設定でそれらのパスを `/llms.mdx/[...path]` ルートへリライトします。
</show>

<show when={props.framework === 'react-router'}>
  React Router では、`/docs/ui.md` のようにドキュメントページと同じ階層にあるパスにはマッチさせられません。そのため、リソースルートで `/llms.mdx` 配下のファイルを配信し、`renderUrl` で `llms.txt` 内のリンクをそちらに向けます。また、ルートルートのミドルウェアでも、マッチしたルート配下にある `/docs/ui.md` などのファイルを配信します。
</show>

<show when={props.framework === 'tanstack-start'}>
  ドキュメントページ `docs/$` は `/docs` 配下のすべてのパスにマッチするため、ドキュメント配下のファイルのルートには `docs/{$}.md` のようなより具体的なパスを使用します。
</show>

<show when={props.framework === 'waku'}>
  API ルートで `/llms.mdx` 配下のファイルを配信し、`renderUrl` で `llms.txt` 内のリンクをそちらに向けます。サーバー上では、`src/middleware` 内の [Hono ミドルウェア](https://hono.dev/docs/guides/middleware)でも `/docs/ui.md` などのファイルをそれぞれのパスで配信します。型定義を利用するため、`hono` を開発依存関係としてインストールしてください。
</show>

<show when={props.framework === 'astro'}>
  1つのエンドポイントで、すべてのファイルをそれぞれのパスにプリレンダリングします。
</show>

<feature>llms/routes</feature>

`serve()` はファイルが存在しないパスに対して `undefined` を返すため、ミドルウェアはリクエストを後続の処理に渡せます。`hideLocale: 'always'` を指定した場合は URL にロケールが含まれないため、言語を `serve()` の第2引数、`files()` の第1引数として渡してください。

<show when={props.framework === 'react-router'}>
  SPA モードでは、`react-router.config.ts` でファイルをプリレンダリングします。React Router は Vite プラグインを適用せずに設定を読み込むため、Vite の `runnerImport` を使ってソースを読み込んでください。

  ```ts title="react-router.config.ts"
  import type { Config } from '@react-router/dev/config';
  import { fumadocsMdx } from 'fumadocs-mdx/vite';
  import { runnerImport } from 'vite';

  export default {
    ssr: false,
    async prerender({ getStaticPaths }) {
      const paths = getStaticPaths();
      const { docsLlms } = (
        await runnerImport<typeof import('./app/lib/source')>('./app/lib/source.ts', {
          plugins: [fumadocsMdx()],
          resolve: { tsconfigPaths: true },
        })
      ).module;

      for (const path of await docsLlms.files())
        paths.push(path === '/llms.txt' || path === '/llms-full.txt' ? path : `/llms.mdx${path}`);
      return paths;
    },
  } satisfies Config;
  ```
</show>

<show when={props.framework === 'tanstack-start'}>
  SPA モードでは、Nitro でファイルをプリレンダリングします。TanStack Start はプリレンダリング対象のパスに末尾スラッシュを付けてリクエストしますが、ファイル用のルートはこれに一致しません。Vite はプラグインを適用せずに設定を読み込むため、`runnerImport` を使ってソースを読み込んでください。

  ```ts title="vite.config.ts"
  import { defineConfig, runnerImport } from 'vite';
  import { fumadocsMdx } from 'fumadocs-mdx/vite';

      plugins: [fumadocsMdx()],
      resolve: { tsconfigPaths: true },

  ).module;

  export default defineConfig({
    plugins: [
      // その他のプラグイン
      nitro({
        prerender: { routes: await docsLlms.files() },
      }),
    ],
  });
  ```
</show>

#### `Accept` [#accept]

<show when={props.framework !== 'astro'}>
  AIエージェントは `Accept` ヘッダーを使って Markdown をリクエストできます。
</show>

<show when={props.framework === 'next'}>
  リクエストが Markdown を優先する場合は、ページの Markdown を返します。

  ```ts title="proxy.ts"
  import { NextRequest, NextResponse } from 'next/server';
  import { isMarkdownPreferred, rewritePath } from 'fumadocs-core/negotiation';

  const { rewrite: rewriteDocs } = rewritePath('/docs{/*path}', '/llms.mdx/docs{/*path}.md');

  export default function proxy(request: NextRequest) {
    const { pathname } = request.nextUrl;
    // `/docs/ui.md` のようなファイルは Next.js 設定の rewrites によって配信されます
    const result =
      isMarkdownPreferred(request) && !/\.(md|txt)$/.test(pathname) && rewriteDocs(pathname);

    if (result) {
      return NextResponse.rewrite(new URL(result, request.nextUrl), {
        headers: { Vary: 'Accept' }, // [!code highlight]
      });
    }

    return NextResponse.next();
  }
  ```
</show>

<show when={props.framework === 'react-router' || props.framework === 'waku'}>
  上記のミドルウェアは、リクエストが Markdown を優先する場合に、ドキュメントページの Markdown を返します。

  <Callout>
    プリレンダリングされたページはミドルウェアの実行前に静的ファイルとして配信されるため、常に
    HTML を返します。
  </Callout>
</show>

<show when={props.framework === 'tanstack-start'}>
  リクエストが Markdown を優先する場合は、ページの Markdown へリダイレクトします。

  ```ts title="src/start.ts"
  import { createMiddleware, createStart } from '@tanstack/react-start';
  import { redirect } from '@tanstack/react-router';
  import { isMarkdownPreferred } from 'fumadocs-core/negotiation';

  const llmMiddleware = createMiddleware().server(({ next, request }) => {
    const url = new URL(request.url);

    // `/docs/ui.md` のようなパスはファイルのルートによって配信されます
    if (
      url.pathname.startsWith('/docs') &&
      !/\.(md|txt)$/.test(url.pathname) &&
      isMarkdownPreferred(request)
    ) {
      url.pathname += '.md';
      throw redirect({ href: url.href, headers: { Vary: 'Accept' } }); // [!code highlight]
    }

    return next();
  });

  export const startInstance = createStart(() => ({
    requestMiddleware: [llmMiddleware],
  }));
  ```
</show>

<show when={props.framework !== 'astro'}>
  同じ URL に2種類の表現が存在することになるため、キャッシュの衝突を防ぐには、レスポンスに `Vary: Accept` を含める必要があります。
</show>

<show when={props.framework === 'next'}>
  <Callout>
    Next.js は App Router のページレスポンスから `Vary` を除去するため、ドキュメントページの HTML レスポンスにはこのヘッダーを
    付与できません。共有キャッシュからドキュメントを配信している場合は、CDN 側で設定してください。
  </Callout>
</show>

<show when={props.framework === 'astro'}>
  ドキュメントページでは、`Accept` ヘッダーに応じて Markdown を返すことはできません。Astro のミドルウェアはリクエスト時にレンダリングされるページでしか実行されず、ドキュメントページはプリレンダリングされるためです。
</show>

## MCP サーバー [#mcp-server]

[MCP](https://modelcontextprotocol.io) サーバーを介してドキュメントをAIエージェントに公開できます。ページの一覧表示、検索、読み取りを行うツールも備えています。

```package-install
npx @fumadocs/cli feature mcp
```

上記の [LLM ルート](#docs-for-llm) に加えて、Streamable HTTP トランスポートを使用する `/api/mcp` ルートが作成されます。

ツールは [`fumadocs-core/mcp`](/docs/headless/utils/mcp) から提供されます。

エージェントを接続するには、次のようにします。

```json
{
  "mcpServers": {
    "docs": { "url": "https://your-site.com/api/mcp" }
  }
}
```

## WebMCP [#webmcp]

<Callout type="warn" title="実験的機能">
  [WebMCP](https://webmachinelearning.github.io/webmcp/) は初期段階の Web 標準で、
  Chrome 149 以降で `#enable-webmcp-testing` フラグを有効にするか、オリジントライアルを通じて利用できます。API は今後
  変更される可能性があります。
</Callout>

前述の MCP サーバーがサイトに接続してくるエージェント向けであるのに対し、WebMCP は読者が閲覧中のページ上で、ブラウザに搭載された AIエージェント
にツールを公開します。

```package-install
npx @fumadocs/cli feature webmcp
```

[LLM ルート](#docs-for-llm)をベースに `WebMCP` コンポーネントを作成します。このコンポーネントは `<RootProvider />` の内側でレンダリングしてください。

* `search_docs` は検索 API ルートにクエリを送信します。`fetchClient` は[他のクライアント](/docs/search)に置き換えることもできます。
* `read_page` は、<show when={props.framework === 'react-router' || props.framework === 'waku'}>`/llms.mdx/docs/page.md`</show><show when={props.framework !== 'react-router' && props.framework !== 'waku'}>`/docs/page.md`</show> からページの Markdown を取得します。

## AIに質問 [#ask-ai]

Fumadocs CLI を使用して、AI チャットダイアログをインストールできます。

    Vercel AI SDK を使用して [LLMGateway](https://llmgateway.io) 向けに自動で設定され、AI 用の `/search` ツールも含まれます。

    LLMGateway は、300 以上の言語モデルへのリクエストをプロキシするオープンソースの API ゲートウェイです。そのため、モデル ID を変更するだけで、同じルートハンドラーのままプロバイダーを切り替えられます。

    LLMGateway の API キーを環境変数に追加します。

    ```dotenv
    LLM_GATEWAY_API_KEY="..."
    ```

    デフォルトでは、ルートは `anthropic/claude-sonnet-5-5` を使用します。LLMGateway がサポートする他のモデルに切り替えるには、`LLM_GATEWAY_MODEL` 環境変数を設定してください。コードを変更する必要はありません。

    ```dotenv
    # https://llmgateway.io/models に掲載されている任意のモデル ID
    LLM_GATEWAY_MODEL="openai/gpt-4o"
    ```

Docs レイアウトは、`aiChat` オプションをもとにチャットをレンダリングします。このオプションはクライアントの状態を受け取るため、レイアウト用のクライアントコンポーネントを作成し、元のレイアウトの代わりに使用してください。

```tsx tab="components/ai/layout.tsx"
'use client';
// Notebook、Glass、Spacious レイアウトも使用できます
import { DocsLayout as Layout, type DocsLayoutProps } from 'fumadocs-ui/layouts/docs';
// インストールしたコンポーネント
import { AIChat, AIChatPanel, useAIChat } from './search';

export function DocsLayout(props: DocsLayoutProps) {
  return (
    <AIChat>
      <ChatLayout {...props} />
    </AIChat>
  );
}

function ChatLayout(props: DocsLayoutProps) {
  const { open, setOpen } = useAIChat();

  return (
    <Layout
      {...props}
      aiChat={{ open, onOpenChange: setOpen, panel: <AIChatPanel />, trigger: true }}
    />
  );
}
```
